## 引言：什么是正则表达式

**定义**：正则表达式（Regular Expression，常缩写为 **regex**、**regexp**）是一种用于描述"文本模式"的微型编程语言。它由两类字符组成：

- **普通字符（字面量，literal）**：匹配其自身，例如字母 `a`、数字 `1`、汉字 `中`。
- **元字符（metacharacter）**：具有特殊含义的字符，例如 `.`、`*`、`+`、`?`、`[`、`]`、`(`、`)`、`\`、`|`、`^`、`$` 等。

正则表达式解决的核心问题是：**用一行简洁的"模式"，代替几十行甚至上百行逐字符扫描的代码**，完成文本的查找、验证、提取、替换与切分。

**历史沿革**：1951 年，数学家 Stephen Cole Kleene 提出"正则集合"（regular sets）概念，用于描述神经网络的数学模型；20 世纪 60—70 年代，Unix 工具 `grep`、`sed`、`awk` 将这一理论引入文本处理，`grep` 的名字即 "**g**lobal **r**egular **e**xpression **p**rint" 的缩写；1990 年代，Perl 语言大幅扩展了正则表达式的表达能力（增加了懒惰量词、零宽断言、命名分组等特性），随后 PHP、Java、JavaScript、Python、Ruby、.NET 等语言纷纷吸收，并逐渐形成事实标准 **PCRE**（Perl Compatible Regular Expressions）。今天，几乎所有主流编程语言、文本编辑器（VS Code、Vim、Emacs）、命令行工具（`grep`、`sed`、`awk`）和数据库（MySQL、PostgreSQL）都内置了正则表达式支持。

**正则表达式的四种典型用途**：

| 用途 | 说明 | 类比 |
| --- | --- | --- |
| 验证（Validate） | 判断整段输入是否符合格式 | 表单校验：邮箱、手机号 |
| 提取（Extract） | 从文本中找出所有匹配的子串 | 从日志中抓取 IP、错误码 |
| 替换（Replace） | 把匹配到的内容替换成别的文本 | 批量改名、脱敏 |
| 切分（Split） | 按模式把文本拆成多段 | 按逗号或空白拆分 CSV |

## 基本概念与术语

为避免歧义，先统一定义本文使用的术语（与 Python 官方文档一致）：

- **模式（pattern）**：正则表达式本身，例如 `\d{4}-\d{2}-\d{2}`。
- **目标字符串（subject string）**：被搜索的文本。
- **匹配（match）**：模式在目标字符串中找到的一段（或多段）满足条件的子串。
- **匹配对象（match object）**：编程语言返回的、携带匹配结果（文本、起止位置、各分组）的对象。
- **引擎（engine）**：负责解释模式并在目标字符串上执行匹配的软件组件。
- **流派（flavor）**：不同语言/工具对正则语法、语义的方言。语法大体相同，细节差异显著。

**重要声明**：正则表达式**不是**一门完全统一的标准。Python 的 `re`、JavaScript 的 `RegExp`、PCRE、POSIX ERE/BRE 之间存在大量细节差异（见第 16 章速查表）。**在实际开发中，一切以目标语言/工具的官方文档为准。** 这也是本教程在关键处反复标注"流派差异"的原因。

## 元字符一览

先给出总表，后续各章逐一详解。下表为各流派通用的 12 个元字符：

| 元字符 | 名称 | 含义（简述） |
| --- | --- | --- |
| `.` | 点号 | 匹配除换行符以外的任意一个字符 |
| `^` | 脱字符 | 匹配字符串（或行）的开头位置 |
| `$` | 美元符 | 匹配字符串（或行）的结尾位置 |
| `*` | 星号 | 前面的元素重复 0 次或多次 |
| `+` | 加号 | 前面的元素重复 1 次或多次 |
| `?` | 问号 | 前面的元素重复 0 次或 1 次；置于量词后表示懒惰 |
| `{` `}` | 花括号 | 指定重复次数，如 `{2,5}` |
| `[` `]` | 方括号 | 字符类，匹配其中任意一个字符 |
| `\` | 反斜杠 | 转义符；也用于引入预定义字符类（如 `\d`） |
| `\|` | 竖线 | 交替（或），如 `a|b` 匹配 a 或 b |
| `(` `)` | 圆括号 | 分组与捕获 |

> **记忆方法**：正则表达式由"**匹配什么字符**（字符类、预定义类、字面量）"和"**在哪里匹配**（锚点）"以及"**匹配多少次**（量词）"三个维度构成，元字符全部服务于这三个维度。

## 字面量与最简单的匹配

### 普通字符匹配自身

模式 `cat` 是一个完全由普通字符组成的正则表达式。在目标字符串 `"I have a cat."` 中，它可以匹配到子串 `cat`：

```python
import re

re.search(r"cat", "I have a cat.")   # 匹配到 "cat"
re.search(r"cat", "I have a dog.")   # 返回 None，未匹配
```

### 大小写敏感

默认情况下，匹配是**大小写敏感**的：`cat` 不会匹配 `Cat` 或 `CAT`。若要忽略大小写，需要使用标志（见第 12 章）：

```python
re.search(r"cat", "I have a Cat.", re.IGNORECASE)  # 匹配到 "Cat"
```

### 子串匹配 vs 整串匹配（重要概念）

这是初学者最容易混淆的概念。绝大多数"搜索"类操作（Python 的 `re.search`、JavaScript 的 `RegExp.test`、`grep`）采用**子串匹配**语义：**只要目标字符串中存在任意一段与模式匹配的子串，就算匹配成功**，不需要整段字符串都匹配。

```python
re.search(r"cat", "concatenate")  # 匹配成功，命中 "con[cat]enate" 中的 "cat"
```

因此，若想"验证整段输入是否符合格式"（例如邮箱、手机号），必须在模式中显式使用锚点 `^` 和 `$`（见第 7 章），或使用专门的整串匹配 API（Python 的 `re.fullmatch`，见第 13 章）。

**本节小结**：普通字符匹配自身；默认大小写敏感；默认是子串匹配而非整串匹配。

## 字符类（Character Class）

### 基本形式

方括号 `[...]` 定义**字符类**：匹配方括号内列出的**任意一个**字符。字符类永远只匹配**一个**字符。

```python
re.search(r"[abc]", "xyz")    # None，"xyz" 中不含 a/b/c
re.search(r"[abc]", "apple")  # 匹配到 "a"
re.search(r"[abc]", "banana") # 匹配到 "b"（第一个命中的字符）
```

### 范围（Range）

用连字符 `-` 表示连续范围。范围按字符编码（ASCII/Unicode 码点）排序：

| 模式 | 含义 |
| --- | --- |
| `[a-z]` | 任意一个小写英文字母 |
| `[A-Z]` | 任意一个大写英文字母 |
| `[0-9]` | 任意一个十进制数字 |
| `[a-zA-Z0-9]` | 任意一个英文字母或数字 |
| `[\u4e00-\u9fff]` | 任意一个汉字（Unicode 基本区） |

可以同时混用单个字符与范围：`[a-f0-9_]` 匹配 a 到 f、0 到 9 或下划线。

### 否定（Negation）

在方括号**开头**放置 `^`，表示"匹配**不在**方括号内的任意一个字符"：

```python
re.search(r"[^0-9]", "abc123")  # 匹配到 "a"（第一个非数字字符）
re.search(r"[^0-9]", "123")     # None，全是数字
```

### 字符类内部的特殊规则（易错点）

字符类内部是一套"子语法"，大部分元字符会**失去特殊含义、退化为字面量**：

| 在字符类外 | 在字符类内 |
| --- | --- |
| `.` 匹配任意字符 | `.` 就是字面量点号 |
| `*`、`+`、`?`、`(`、`)`、`$` 有特殊含义 | 均为字面量 |
| `-` 表示范围 | 位于开头或结尾时是字面量，如 `[-a]`、`[a-]` |
| `^` 表示锚点 | 位于开头时表示否定，如 `[^a]`；位于其他位置是字面量 |
| `\` 转义 | 仍用于转义，如 `[\]]` 匹配右方括号本身 |
| `]` 表示字符类结束 | 需要转义 `\]`，或放在开头，如 `[]a]`（Python、PCRE 等均支持） |

> **示例**：`[a\-z]` 匹配三个字符之一：`a`、`-`、`z`（`-` 被转义，不再是范围符）。
> **示例**：`[.]` 匹配字面量点号，与 `\.` 等价；所以"匹配文件扩展名"应写 `\.(txt|md)$` 或 `[.](txt|md)$`，而**不能**写 `.txt`（那是"任意字符 + txt"）。

**本节小结**：`[...]` 匹配一个字符；`-` 表示范围；开头的 `^` 表示否定；字符类内大部分元字符退化为字面量。

## 预定义字符类与转义

### 四个常用预定义类及其否定

用反斜杠引导的简写字符类，覆盖最高频的匹配需求：

| 模式 | 含义 | 等价写法（ASCII 下） |
| --- | --- | --- |
| `\d` | 一个十进制数字 | `[0-9]` |
| `\D` | 一个非数字字符 | `[^0-9]` |
| `\w` | 一个"单词字符" | `[A-Za-z0-9_]`（字母、数字、下划线） |
| `\W` | 一个非单词字符 | `[^A-Za-z0-9_]` |
| `\s` | 一个空白字符 | `[ \t\n\r\f\v]`（空格、制表、换行、回车、换页、垂直制表） |
| `\S` | 一个非空白字符 | `[^ \t\n\r\f\v]` |

```python
re.findall(r"\d+", "2024 年销售 1234 件")     # ['2024', '1234']
re.findall(r"\w+", "hello, world_2024!")     # ['hello', 'world_2024']
re.split(r"\s+", "a  b\tc\n d")              # ['a', 'b', 'c', 'd']
```

### 流派差异：`\d` 与 `\w` 的 Unicode 语义（重要）

**Python 3 中，`\d`、`\w`、`\s` 默认匹配 Unicode 字符**，而不仅是 ASCII：

```python
re.findall(r"\d+", "价格为 ٣٤٥ 元")   # ['٣٤٥']，阿拉伯-印度数字也是 \d
re.findall(r"\w+", "你好，世界！")     # ['你好', '世界']，汉字也是 \w
```

而 JavaScript（无 `u` 标志时）与多数旧工具中，`\d` 仅匹配 `[0-9]`，`\w` 仅匹配 `[A-Za-z0-9_]`。**跨语言移植正则时，这一差异是最常见的隐性 bug 来源之一。**

若在 Python 中希望严格按 ASCII 语义匹配，可使用 `re.ASCII` 标志（见第 12 章）：

```python
re.findall(r"\w+", "你好，世界！", re.ASCII)  # []，汉字不再是 \w
```

### 任意字符：点号 `.`

`.` 匹配**除换行符（`\n`，部分流派还包括 `\r`）以外的任意一个字符**。它不匹配"任意内容"，而是"任意一个非换行字符"：

```python
re.search(r"a.b", "axb")   # 匹配 "axb"（x 可以是任何非换行字符）
re.search(r"a.b", "a\nb")  # None，点号不匹配换行
```

若希望 `.` 也匹配换行，使用 `re.DOTALL` 标志（Python）/ `s` 修饰符（PCRE）/ `s` 标志（JavaScript）。

### 转义：`\`

反斜杠有两个作用：

1. **把元字符转义为字面量**：`\.` 匹配点号、`\*` 匹配星号、`\\` 匹配反斜杠本身、`\[` 匹配左方括号。
2. **引入预定义字符类**：`\d`、`\w`、`\s`、`\b`（词边界，见第 7 章）等。

```python
re.findall(r"\d+\.\d+", "π≈3.14，e≈2.718")  # ['3.14', '2.718']
```

> **Python 特别提醒**：请始终使用**原始字符串（raw string）**书写模式，即 `r"..."` 而非 `"..."`。否则 `"\d"` 中的 `\d` 会被 Python 解释为转义序列而报错或产生歧义；例如 `"\b"` 实际是退格符 `\x08`，会让正则行为完全错误。

**本节小结**：`\d \w \s` 及其大写否定形式是高频预定义类；Python 3 默认按 Unicode 语义解释它们；`.` 匹配任意非换行字符；`\` 用于转义元字符或引入预定义类。

## 锚点与位置（Anchor）

锚点匹配的是**位置**，而不是字符。它们"零宽度"——不消耗任何字符，只断言当前位置满足某种条件。

### 行首 `^` 与行尾 `$`

| 锚点 | 默认含义 | 多行模式（`re.MULTILINE`）下 |
| --- | --- | --- |
| `^` | 字符串开头 | 每一行的开头（每个 `\n` 之后） |
| `$` | 字符串结尾，**或末尾换行符之前** | 每一行的结尾（每个 `\n` 之前） |

```python
re.search(r"^\d+", "123abc")   # 匹配 "123"（字符串以数字开头）
re.search(r"^\d+", "a123")     # None（字符串不以数字开头）
re.search(r"\d+$", "abc123")   # 匹配 "123"（字符串以数字结尾）
re.search(r"\d+$", "abc123\n") # 匹配 "123"（$ 也匹配末尾换行之前的位置）
```

> **注意**：`$` 匹配"字符串结尾**或末尾换行符之前**"是 Python、JavaScript、PCRE 的常见行为；若只想匹配绝对的字符串结尾，用 `\Z`（Python）或 `\z`（PCRE、Ruby、.NET）。

### 词边界 `\b` 与 `\B`

`\b` 匹配**单词边界**：即 `\w`（单词字符）与 `\W`（非单词字符）之间的位置，也匹配字符串首尾处（若首尾字符是单词字符）。`\B` 是它的补集：匹配**非**单词边界的位置。

```python
re.findall(r"\bcat\b", "a cat, a catalog, concat")  # ['cat']，只匹配独立的词 cat
re.findall(r"\bcat\b", "cat")                       # ['cat']，\b 也匹配字符串首尾
```

> **经典应用**：搜索"独立单词"时必须用 `\b` 包裹。`\bcat\b` 不会命中 `catalog` 中的 `cat`，而 `cat` 会。
> **注意**：`\b` 依赖于 `\w` 的定义。在 Python 3 默认 Unicode 语义下，汉字属于 `\w`，因此 `\b` 不会把"中文与英文"交界当作词边界——这与 ASCII 语义下的行为不同。

### 字符串级锚点：`\A`、`\Z`、`\z`

| 锚点 | 含义 | 支持流派 |
| --- | --- | --- |
| `\A` | 仅匹配字符串开头（不受多行模式影响） | Python、PCRE、Java、.NET、Ruby |
| `\Z` | 仅匹配字符串结尾（Python；在末尾换行之前） | Python、Ruby |
| `\z` | 仅匹配字符串的绝对结尾（`\Z` 的严格版） | PCRE、Ruby、Java、.NET；**Python `re` 不支持** |

```python
re.search(r"\A\d+\Z", "123")      # 匹配（严格整串匹配）
re.search(r"\A\d+\Z", "123\n")    # None（\Z 不匹配换行之前的位置）
re.search(r"\A\d+$", "123\n")     # 匹配（$ 匹配换行之前）
```

### `re.match` 与 `re.search` 的本质区别

Python 的 `re.match` 要求模式**从字符串开头**开始匹配（等价于模式开头隐式带有 `^` 语义，但它匹配的是"开头起的一段"，不要求到结尾）；`re.search` 在字符串中**任意位置**搜索；`re.fullmatch` 要求**整个字符串**与模式匹配（等价于 `\A...\Z`）。三者对应三种典型需求：前缀检查、包含查找、整串验证。

```python
re.match(r"\d+", "123abc")    # 匹配 "123"（从开头）
re.match(r"\d+", "abc123")    # None
re.search(r"\d+", "abc123")   # 匹配 "123"（任意位置）
re.fullmatch(r"\d+", "123")   # 匹配 "123"
re.fullmatch(r"\d+", "123abc")  # None（要求整串）
```

**本节小结**：`^ $` 是行级锚点，`\b \B` 是词边界，`\A \Z \z` 是字符串级锚点；整串验证必须用锚点或 `fullmatch`。

## 量词与贪婪/懒惰匹配

量词（quantifier）规定**前面的元素重复多少次**。它是正则中最常用也最易踩坑的部分。

### 量词一览

| 量词 | 含义 | 等价形式 |
| --- | --- | --- |
| `*` | 重复 0 次或多次 | `{0,}` |
| `+` | 重复 1 次或多次 | `{1,}` |
| `?` | 重复 0 次或 1 次（可有可无） | `{0,1}` |
| `{n}` | 恰好重复 n 次 | — |
| `{n,}` | 至少重复 n 次 | — |
| `{n,m}` | 重复 n 到 m 次 | — |

```python
re.findall(r"colou?r", "color colour")     # ['color', 'colour']，u 可有可无
re.fullmatch(r"\d{4}-\d{2}-\d{2}", "2024-03-08")  # 匹配，格式检查
re.findall(r"\d{2,3}", "1 22 333 4444")    # ['22', '333', '444']，注意 4444 被拆为 444 + 4
```

> **注意**：`{n,m}` 与 `{n,}` 中的逗号不能省略；`{n,m}` 的 m 不能小于 n。模式 `\d{2,3}` 对 `4444` 的匹配结果取决于引擎的**贪婪**策略，见下节。

### 贪婪（Greedy）与懒惰（Lazy）

默认情况下，量词是**贪婪**的：在保证整体匹配成功的前提下，**尽可能多地**匹配字符。在量词后追加 `?` 可改为**懒惰**（非贪婪）：**尽可能少地**匹配字符。

| 贪婪 | 懒惰（加 `?`） |
| --- | --- |
| `*` | `*?` |
| `+` | `+?` |
| `?` | `??` |
| `{n,}` | `{n,}?` |
| `{n,m}` | `{n,m}?` |

**经典示例：HTML 标签提取**。对字符串 `<b>加粗</b>和<i>斜体</i>`：

```python
re.findall(r"<.+>", "<b>加粗</b>和<i>斜体</i>")
# 贪婪结果：['<b>加粗</b>和<i>斜体</i>']，一口气吞到最后一个 >
re.findall(r"<.+?>", "<b>加粗</b>和<i>斜体</i>")
# 懒惰结果：['<b>', '</b>', '<i>', '</i>']，每次只匹配最短的 <...>
```

**理解机制（回溯）**：引擎从左向右尝试。贪婪量词先"吃到不能再吃"，若后续无法匹配成功，则**回退（回溯，backtrack）**一个字符再试，直到整体匹配或彻底失败。懒惰量词则相反：先"只吃最少"，不行再多吃一个。

> **反直觉示例**：`\d{2,3}` 匹配 `4444` 时，贪婪引擎先尝试 3 位（`444`），剩余 `4` 无法匹配（没有更多量词要求），于是整体匹配成功，结果为 `444`；随后继续扫描，`4` 单独不满足最少 2 位，因此 `findall` 返回 `['444']`，而不是"从第 2 位开始再匹配"。这体现了**匹配从左到右、尽可能长（贪婪）**的规则。

### 占有量词（Possessive）

在量词后追加 `+` 得到**占有量词**：`*+`、`++`、`?+`、`{n,m}+`。占有量词也"尽可能多"地匹配，但**匹配后绝不回退**（不参与回溯）。

- 支持：PCRE、Java、.NET、Ruby；**Python 3.11 起支持**（此前需第三方 `regex` 模块）；JavaScript、Go 不支持。
- 作用：牺牲"失败时的补救能力"换取性能与确定性，常用于防止灾难性回溯（见第 15 章）。

```python
re.fullmatch(r"a*+a", "aaa")   # Python 3.11+：None！
# a*+ 贪婪吞掉全部 3 个 a 且不回退，后续 a 无处可匹配，整体失败
re.fullmatch(r"a*a", "aaa")    # 匹配："a*" 先吃 3 个，回溯让出 1 个给最后的 a
```

### 回溯的成本与灾难性回溯

回溯是正则引擎的基本机制，但**嵌套的量词可能引发指数级回溯**。经典灾难示例：

```
模式：^(a+)+$
输入：aaaaaaaaaaaaaaaaaaaaaaaaaaaaab   （26 个 a 后跟一个 b）
```

`(a+)+` 意味着"若干组 a"，引擎会尝试把 26 个 a 拆分成各种组数（1 组、2 组、13 组……）的所有组合方式，全部失败后才得出结论——所需时间随 a 的个数**指数增长**。此类模式在用户可控输入下可能被用来发起 **ReDoS**（正则表达式拒绝服务攻击）。

防护手段见第 15 章（原子组、占有量词、RE2 引擎、输入长度限制、超时等）。

**本节小结**：量词规定重复次数；默认贪婪、加 `?` 变懒惰；加 `+` 变占有（部分流派支持）；贪婪与懒惰都依赖回溯，嵌套量词可能引发灾难性回溯。

## 分组、捕获与反向引用

圆括号 `(...)` 在正则中有三个作用：**分组**（把多个元素当作一个整体应用量词）、**捕获**（记录匹配的子文本）、以及后面要讲的**断言**（第 11 章）。

### 分组：把"几个元素"变成"一个元素"

```python
re.findall(r"(ab)+", "ababab")   # 匹配 "ababab"（ab 作为整体重复）
re.findall(r"ab+", "abbb")       # 匹配 "abbb"（只有 b 重复）——对比上例！
```

### 捕获与编号

每个捕获分组在匹配成功后，会把命中的文本单独保存。分组**按左括号出现的顺序从 1 开始编号**（第 0 组是整体匹配）：

```python
m = re.search(r"(\d{4})-(\d{2})-(\d{2})", "日期：2024-03-08")
m.group(0)   # '2024-03-08'，整体
m.group(1)   # '2024'
m.group(2)   # '03'
m.group(3)   # '08'
m.groups()   # ('2024', '03', '08')，全部捕获组
```

**嵌套分组的编号规则**：按**左括号出现的先后顺序**编号，与括号的嵌套深度无关：

```
模式: ((a)(b(c))) 
编号:  1  2   3
     组1 = 整个 "(a)(b(c))"，组2 = "a"，组3 = "b(c)"，组4 = "c"
```

### 反向引用（Backreference）

在**模式内部**用 `\1`、`\2`……引用前面捕获组匹配到的**具体内容**（而不是模式本身）：

```python
re.search(r"(\w+)\s+\1", "go go")       # 匹配 "go go"（\1 引用前面匹配到的 "go"）
re.search(r"(\w+)\s+\1", "go stop")     # None（"go" 后不是 "go"）
re.fullmatch(r"<(\w+)>.*</\1>", "<b>text</b>")   # 匹配，成对标签校验
re.fullmatch(r"<(\w+)>.*</\1>", "<b>text</i>")   # None，标签不配对
```

> **注意**：`\1` 引用的是**捕获的内容**（匹配到的具体文本），不是"再次执行该分组的模式"。`(\d)\1` 匹配 `11`、`55` 这类重复数字，而不是"任意两个数字"。

### 命名分组（Named Group）

数字编号在模式复杂时难以维护，多数流派支持给分组起名字：

| 流派 | 命名分组语法 | 模式内反向引用 | 替换中引用 |
| --- | --- | --- | --- |
| Python `re` | `(?P<name>...)` | `(?P=name)` | `\g<name>` |
| PCRE / .NET / Java / Ruby | `(?<name>...)` 或 `(?'name'...)` | `\k<name>` | `${name}` |
| JavaScript（ES2018 起） | `(?<name>...)` | `\k<name>` | `$<name>` |

```python
m = re.search(r"(?P<year>\d{4})-(?P<month>\d{2})", "2024-03-08")
m.group("year")    # '2024'
m.groupdict()      # {'year': '2024', 'month': '03'}

# 模式内引用命名组（Python）
re.search(r"(?P<word>\w+) (?P=word)", "repeat repeat")  # 匹配
```

### 非捕获分组 `(?:...)`

如果只需要分组、不需要捕获（例如只是给量词划定范围），使用 `(?:...)` 避免产生额外分组编号。它不保存内容，也不影响编号顺序：

```python
re.findall(r"(?:ab)+", "abab")     # ['abab']
re.findall(r"(ab)+", "abab")       # ['ab']，注意！findall 只返回捕获组的内容
```

> **findall 陷阱**：Python 的 `re.findall` 在模式**含有捕获组时，返回的是各组内容（元组），而不是整体匹配**。若只想拿整体匹配，用非捕获分组 `(?:...)`，或改用 `re.finditer`（见第 13 章）。

### 替换中的引用

在替换文本中，`\1`、`\2` 表示"把第 n 组捕获的内容粘到这里"（具体语法随流派不同，见上表；Python 中 `\g<1>` 写法可避免 `\10` 之类的歧义）：

```python
re.sub(r"(\w+), (\w+)", r"\2, \1", "Smith, John")      # 'John, Smith'
re.sub(r"(?P<first>\w+) (?P<last>\w+)", r"\g<last> \g<first>", "Eric Idle")  # 'Idle Eric'

# 替换文本也可以是函数：函数接收 Match 对象，返回替换串
re.sub(r"\b\w", lambda m: m.group().upper(), "hello world")   # 'Hello World'
```

> **注意**：Python 的 `re.sub` 中，替换串里**没有参与匹配的分组**引用会被替换为空字符串（而不是报错），`m.group(n)` 在未参与匹配时返回 `None`。两种行为都需留意。

**本节小结**：`(...)` 捕获并按左括号顺序编号；`\1` 在模式内引用已捕获的内容；命名分组 `(?P<name>...)` 提升可读性；`(?:...)` 只分组不捕获；替换中用 `\1`/`\g<name>` 引用捕获内容。

## 交替（Alternation）

### 基本用法

竖线 `|` 表示"**或**"，把模式分成多个分支，匹配其中任意一个分支：

```python
re.fullmatch(r"cat|dog", "cat")   # 匹配
re.fullmatch(r"cat|dog", "dog")   # 匹配
re.fullmatch(r"cat|dog", "cow")   # None
```

### 优先级：交替最低

`|` 的优先级**低于**字符连接（即"挨着写的字符"）。因此 `gr(a|e)y` 必须用括号限定范围，否则 `gra|ey` 表示"匹配 `gra` **或** `ey`"：

```python
re.search(r"gr(a|e)y", "grey")   # 匹配 "grey"
re.search(r"gr(a|e)y", "gray")   # 匹配 "gray"
re.search(r"gra|ey", "grey")     # 匹配 "ey"（不是 "grey"！）
```

### 交替 vs 字符类

- 单个字符的"或"应优先用字符类：`[ab]` 比 `a|b` 更简洁、性能更好。
- 多字符分支、或需要配合捕获/断言时，才用交替：`(cat|dog)s?`。

### 分支顺序与"最先匹配"规则

默认引擎按**从左到右**尝试各分支，**第一个成功的分支胜出**（不是"最长"）：

```python
re.search(r"cat|category", "category")   # 匹配 "cat"（第一个分支先成功）
```

> **POSIX 差异**：POSIX 流派（`grep`、`awk` 等）要求"**最左最长**"匹配，会选 `category`。这在移植正则到 Unix 工具时需要注意。

**本节小结**：`|` 是优先级最低的"或"；多字符分支要加括号；单字符"或"用字符类；默认流派取"最先匹配成功"的分支。

## 零宽断言（Lookaround）

断言（assertion）匹配的是**位置条件**，不消耗字符。第 7 章的锚点（`^ $ \b`）是内置断言；本节是**自定义断言**：前瞻与后顾。

### 四种断言

| 名称 | 语法 | 含义 |
| --- | --- | --- |
| 正向前瞻（lookahead） | `(?=...)` | 当前位置**之后**必须能匹配 `...` |
| 负向前瞻（negative lookahead） | `(?!...)` | 当前位置**之后**必须**不能**匹配 `...` |
| 正向后顾（lookbehind） | `(?<=...)` | 当前位置**之前**必须能匹配 `...` |
| 负向后顾（negative lookbehind） | `(?<!...)` | 当前位置**之前**必须**不能**匹配 `...` |

```python
# 正向前瞻：匹配后面跟着"元"的数字（只输出数字本身）
re.findall(r"\d+(?=元)", "苹果5元，香蕉3元，梨2元")   # ['5', '3', '2']

# 负向前瞻：匹配后面不是 "bar" 的 "foo"
re.findall(r"foo(?!bar)", "foo foo bar foobar")     # ['foo', 'foo']

# 正向后顾：匹配前面是 "￥" 的数字
re.findall(r"(?<=￥)\d+", "￥100 和 $50")           # ['100']

# 负向后顾：匹配前面不是数字的 3 位数字
re.findall(r"(?<!\d)\d{3}(?!\d)", "123 4567")       # ['123']（4567 是 4 位，且 567 前有数字）
```

### 关键性质：零宽度

断言**不把字符算进匹配结果**。上例中 `\d+(?=元)` 匹配的是 `5`，`元` 只是"检查条件"，不出现在结果里，也不推进匹配位置。断言可以连续使用，实现"多重条件"：

```python
# 同时要求：以 http 开头、以 com 结尾、中间任意非空白
re.fullmatch(r"(?=http)\S*(?<=com)", "http://example.com")   # 匹配
```

### 应用：密码强度校验（多重断言叠加）

零宽断言最常见的应用是"一个模式同时满足多个互不重叠的条件"：

```python
# 至少 8 位，且同时包含小写字母、大写字母、数字、特殊字符
pattern = r"^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)(?=.*[^A-Za-z0-9]).{8,}$"

re.fullmatch(pattern, "Passw0rd!")   # 匹配
re.fullmatch(pattern, "password1")   # None（缺大写与特殊字符）
```

四个 `(?=...)` 各自从开头独立检查全文，互不干扰，最后 `.{8,}` 保证长度。

### 后顾断言的限制（流派差异）

- **Python `re`**：后顾断言必须是**固定宽度**——`(?<=ab)` 合法，`(?<=\d+)` 报错；多个分支宽度也必须一致，`(?<=a|bc)` 非法（可用 `(?<=a|b)` 或改写成 `(?<=[ab]c?)` 这类同宽形式，或用第三方 `regex` 模块）。
- **PCRE、Java**：允许有明确上限的变宽后顾，如 `(?<=\d{1,3})`。
- **.NET、JavaScript（V8 实现）**：支持任意变宽后顾。
- **Go（RE2）**：完全不支持后顾。

```python
re.search(r"(?<=\d{2})年", "2024年")   # 匹配 "年"（定宽 {2} 合法，各版本均支持）
# re.search(r"(?<=\d+)年", "2024年")   # 报错：后顾断言必须为固定宽度
```

> **前瞻无此限制**：前瞻在后顾之前被各流派广泛支持，且没有宽度限制。

**本节小结**：`(?=...)` `(?!...)` 前瞻、`(?<=...)` `(?<!...)` 后顾都是零宽断言，用于叠加"位置条件"；Python 的后顾必须定宽；断言是实现密码校验、上下文提取的核心工具。

## 标志与内联修饰符（Flags）

标志（flag）改变引擎的全局行为。标志可以在 API 调用时传入，也可以写在模式开头（内联修饰符）。

### Python `re` 的标志

| 标志 | 内联写法 | 作用 |
| --- | --- | --- |
| `re.IGNORECASE`（`I`） | `(?i)` | 忽略大小写 |
| `re.MULTILINE`（`M`） | `(?m)` | `^` `$` 改为匹配每行的行首行尾 |
| `re.DOTALL`（`S`） | `(?s)` | `.` 匹配包括换行在内的任意字符 |
| `re.VERBOSE`（`X`） | `(?x)` | 详细模式：忽略空白与 `#` 注释，允许模式换行 |
| `re.ASCII`（`A`） | `(?a)` | `\d \w \s` 等仅匹配 ASCII 字符 |
| `re.UNICODE`（`U`） | `(?u)` | 默认行为：按 Unicode 语义匹配 |

```python
re.search(r"cat", "CAT", re.IGNORECASE)     # 匹配
re.search(r"^a", "x\na", re.MULTILINE)      # 匹配（第二行行首）
re.search(r"a.b", "a\nb", re.DOTALL)        # 匹配
```

### 详细模式（VERBOSE / `x`）：把正则写成"说明书"

`re.VERBOSE` 允许在模式中写空白与注释，显著提升复杂正则的可读性。**这是所有"说明书式"正则的必备写法**：

```python
phone = re.compile(r"""
    ^          # 字符串开头
    (13[0-9]|14[01456879]|15[0-35-9]|16[2567]|17[0-8]|18[0-9]|19[0-35-9])  # 前三位号段
    \d{8}      # 后八位数字
    $          # 字符串结尾
""", re.VERBOSE)
phone.fullmatch("13812345678")   # 匹配
```

> **注意**：`(?x)` 模式下，若要匹配字面空格或 `#`，必须转义：`\ `、`\#`，或用字符类 `[ ]`、`[#]`。

### 内联修饰符的开关与作用域

内联修饰符可以组合、开与关：`(?i)` 开启忽略大小写，`(?-i)` 关闭（PCRE 语法；Python 3.6 起支持 `(?i:...)` 局部作用域，Python 的 `(?-i)` 于 3.11 起支持）：

```python
# 局部开关（Python 3.6+）：只有括号内忽略大小写
re.search(r"(?i:hello) world", "HELLO world")   # 匹配
re.search(r"(?i:hello) world", "HELLO WORLD")   # None（world 部分仍区分大小写）
```

**本节小结**：标志改变全局语义：`i` 忽略大小写、`m` 多行锚点、`s` 点号匹配换行、`x` 详细模式、`a` ASCII 语义；内联写法 `(?flags)` 写在模式开头或作用于分组局部。

## Python 实战：re 模块详解

本节把 Python `re` 模块的完整 API 串起来，并给出每个函数的使用要点与陷阱。这是把前面所有语法落到代码的关键一章。

### 核心函数总览

| 函数 | 作用 | 返回 |
| --- | --- | --- |
| `re.compile(pattern, flags=0)` | 预编译模式，返回 `Pattern` 对象 | `Pattern` |
| `pattern.search(string)` | 在字符串中查找第一个匹配 | `Match` 或 `None` |
| `pattern.match(string)` | 从字符串开头匹配 | `Match` 或 `None` |
| `pattern.fullmatch(string)` | 要求整个字符串匹配 | `Match` 或 `None` |
| `pattern.findall(string)` | 查找所有匹配 | 字符串列表 / 元组列表 |
| `pattern.finditer(string)` | 查找所有匹配 | 迭代器（`Match`） |
| `pattern.sub(repl, string, count=0)` | 替换所有匹配 | 新字符串 |
| `pattern.split(string, maxsplit=0)` | 按匹配切分 | 字符串列表 |

```python
# 预编译：同一模式多次使用时避免重复编译（也便于集中管理）
pattern = re.compile(r"\b\w{4}\b", re.IGNORECASE)
pattern.findall("Four word here")   # ['Four', 'word', 'here']
```

### `Match` 对象常用方法

| 方法/属性 | 作用 |
| --- | --- |
| `m.group()` / `m.group(0)` | 整体匹配文本 |
| `m.group(n)` | 第 n 个捕获组文本（未参与匹配时为 `None`） |
| `m.groups()` | 所有捕获组组成的元组 |
| `m.groupdict()` | 所有**命名**组组成的字典 |
| `m.start()` / `m.end()` | 匹配起止下标 |
| `m.span()` | `(start, end)` 元组 |

```python
m = re.search(r"(\d{4})-(\d{2})-(\d{2})", "今天 2024-03-08 发布")
m.span()          # (3, 13)
m.group(2)        # '03'
m.start(2)        # 8
```

### `findall` 与分组（再次强调陷阱）

```python
re.findall(r"(\w+)@(\w+)", "a@b c@d")    # [('a','b'), ('c','d')]——有分组返回元组列表！
re.findall(r"(?:\w+)@(?:\w+)", "a@b c@d")  # ['a@b', 'c@d']——非捕获组不触发该行为
```

### `split`：切分

```python
re.split(r"[,\s]+", "a, b  c,d")      # ['a', 'b', 'c', 'd']
re.split(r"(\d+)", "a1b22c")          # ['a', '1', 'b', '22', 'c']——含捕获组时保留分隔符
```

> 含捕获组时，`split` 会把分隔符本身也放进结果列表，这在解析"键值对"等场景很有用。

### `sub`：替换

```python
re.sub(r"\d+", "#", "共 12 个，价格 99 元")            # '共 # 个，价格 # 元'
re.sub(r"\d+", "#", "共 12 个", count=1)               # '共 # 个'，最多替换 1 次
re.sub(r"(\w+) (\w+)", r"\2 \1", "John Smith")         # 'Smith John'
```

### 三个验证函数的选用决策

| 需求 | 用哪个 |
| --- | --- |
| "这段文本是否**以** XX 开头" | `match` |
| "这段文本里**是否含** XX" | `search` |
| "这段文本**整体是否**符合 XX 格式" | `fullmatch`，或模式用 `^...$` |

**本节小结**：`compile` 预编译；`search/match/fullmatch` 对应三种匹配起点语义；`findall` 注意分组陷阱；`split` 含捕获组保留分隔符；`sub` 支持引用与函数替换。

## 常用模式库（附分析与局限性）

以下模式均给出含义与**局限性说明**，实际使用请按需求调整。正则只能做"句法级"检查，**无法做"语义级"验证**（例如邮箱是否存在、日期是否真实）。

### 邮箱地址

```python
email = r"^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$"
```

- 匹配：`user.name+tag@example.com`、`a@b.co`
- 局限：这只是常用简化版。RFC 5322 定义的完整邮箱语法极其复杂（允许引号字符串、注释等），任何"一行正则"都只是近似；实际系统还应做域名 MX 记录检查等语义验证。

### IPv4 地址

```python
ipv4 = r"^(25[0-5]|2[0-4]\d|1\d\d|[1-9]?\d)(\.(25[0-5]|2[0-4]\d|1\d\d|[1-9]?\d)){3}$"
```

- 匹配：`192.168.1.1`；拒绝 `256.1.1.1`、`01.2.3.4`（按严格写法）
- 说明：`25[0-5]`（250–255）、`2[0-4]\d`（200–249）、`1\d\d`（100–199）、`[1-9]?\d`（0–99，且拒绝前导零）。IPv6 需另行处理。

### 日期（YYYY-MM-DD）

```python
date = r"^\d{4}-(0[1-9]|1[0-2])-(0[1-9]|[12]\d|3[01])$"
```

- 匹配：`2024-03-08`；拒绝 `2024-13-01`、`2024-00-10`
- 局限：**不校验月份天数是否真实**（`2024-02-31` 会通过）。日期真实性校验（闰年、大小月）建议交给 `datetime` 等专门库，而不是正则。

### 中国大陆手机号

```python
cn_mobile = r"^1[3-9]\d{9}$"
```

- 匹配：`13812345678`；拒绝 `12812345678`
- 说明：1 开头、第二位 3–9、共 11 位。号段会随工信部发放而更新，`[3-9]` 是常见折中写法；更精确的号段表需持续维护。

### 汉字

```python
han = r"[\u4e00-\u9fff]"        # 单个汉字（Unicode 基本区）
re.findall(r"[\u4e00-\u9fff]+", "Hello 世界！")   # ['世界']
```

- 局限：不覆盖扩展区汉字（`\u3400-\u4dbf` 等）。若需完整汉字属性匹配，Python 可借助支持 `\p{Han}` 的第三方 `regex` 模块。

### 数字与千分位

```python
re.findall(r"\d+(?:\.\d+)?", "价格 99.5 与 100 元")   # ['99.5', '100']

# 千分位加逗号：在"数字组末尾"前插入逗号
re.sub(r"\B(?=(\d{3})+(?!\d))", ",", "1234567.891")   # '1,234,567.891'
```

### URL

```python
url = r"^https?://[\w.-]+(?::\d+)?(?:/\S*)?$"
```

- 匹配：`https://example.com`、`http://a.io:8080/path?q=1`
- 局限：简化版；完整 URL 校验建议用标准库 `urllib.parse`。

### 其他高频小模式

| 用途 | 模式 |
| --- | --- |
| 空白行 | `^\s*$` |
| 去掉首尾空白 | `re.sub(r"^\s+|\s+$", "", s)`（或直接用 `s.strip()`） |
| 引号内的文本 | `"[^"]*"`（比 `".*?"` 更高效且不会跨引号） |
| 成对标签 | `<(\w+)>.*?</\1>`（配合第 8 章懒惰量词与第 9 章反向引用） |
| 重复单词（打字错误检测） | `\b(\w+)\s+\1\b` |

**本节小结**：常用模式都要"知其局限"——正则做句法校验、不做语义校验；涉及日期真实性、域名存在性等，应交给专门库。

## 性能、安全与最佳实践

### 灾难性回溯（Catastrophic Backtracking）与 ReDoS

回顾第 8.4 节的示例：`^(a+)+$` 对"26 个 a + b"的输入需要指数级时间。**当输入来自用户且正则中存在嵌套量词时，这就是安全漏洞（ReDoS）**。典型高危模式特征：

- 嵌套的量词：`(a+)+`、`(a*)*`、`(a|a)+`、`(\w+\s?)*` 等。
- 量词作用于"可以匹配空串或极短串"的分支。

**防护手段（按推荐顺序）**：

1. **改写模式**，消除嵌套量词（多数情况可以做到）。
2. **用原子组或占有量词**阻断回溯：`(?>a+)+`（原子组，Python 3.11+ 与 PCRE 支持）、`a*+`（占有量词）。
3. **使用线性时间引擎**：Go 的 `regexp`（RE2）、Python 的 `google-re2`、Rust 的 `regex` crate，它们不支持回溯类特性（反向引用、后顾等），但保证最坏情况线性时间。
4. **运行时防护**：限制输入长度、限制匹配次数/超时（如 Java 的 `Matcher` 无内置超时，可自行用线程+中断；Python 可借助 `signal` 或第三方 `regex` 模块的超时参数 `timeout=`）。

```python
# 原灾难模式：^(a+)+$ 对 "26 个 a + b" 需要指数级时间（最终匹配失败）
# 原子组版本：^(?>a+)+$ 同样快速失败——匹配过程不回溯，没有指数爆炸
re.fullmatch(r"(?>a+)+$", "aaaaaaaaaaaaaaaaaaaaaaaaaaaaab")  # 快速返回 None
```

### 不要用正则解析 HTML / JSON / 嵌套结构

正则适合处理**规则的、扁平的**文本。HTML、XML、JSON、编程语言源码具有**嵌套结构**（标签套标签、括号套括号），正则无法可靠解析——业界经典名言："如果你用正则解析 HTML，问题会多到让你后悔。"请使用专门的解析器：`html.parser`、`BeautifulSoup`、`json`、`xml.etree.ElementTree` 等。

### 可读性最佳实践

1. **复杂模式一律用详细模式**（`re.VERBOSE` / `(?x)`），配注释与换行（见第 12.2 节）。
2. **用命名分组**代替 `\1 \2`，模式与替换代码都更可读。
3. **为模式写单元测试**：至少包含"应匹配/应拒绝"两类用例，边界值（空串、超长串、Unicode）必测。
4. **优先否定字符类而非懒惰量词**：`"[^"]*"` 比 `".*?"` 更快、更不容易出意外。
5. **优先字符串方法**：`str.startswith`、`str.split`、`str.strip` 能解决就不要上正则。

## 综合实战案例：访问日志的解析、统计与脱敏

前面的章节按知识点逐个讲解；本章用一个**完整任务**把它们串起来，演示"拿到真实文本后，如何一步一步设计正则、并用它完成一套工作流"。

**任务需求**：

1. **解析**：把每行访问日志解析成结构化字段（时间、级别、用户、IP、方法、路径、状态码、耗时、消息）；
2. **容错**：格式异常的行不能被"带偏"，应被识别并跳过；
3. **统计**：请求总数、各级别数量、平均耗时、最慢请求、错误请求明细；
4. **脱敏**：把日志中的 IP 与消息内容打码后输出；
5. **上下文提取**：用零宽断言做第二遍"按条件取字段"。

下面每步都会标注"用到了第几章的知识"，方便对照复习。

### 样例数据

刻意准备了 7 行日志，其中**第 6 行是坏数据**（IP 为 `999.1.1.1`，非法），**第 7 行含转义引号**（消息为 `say \"hi\"`）——这两行是"埋雷"，用来检验容错与高级引号模式：

```python
log_text = """\
2024-03-08 14:30:22 [INFO] user:alice ip:192.168.1.10 method:GET path:/api/orders/2024 status:200 cost:35ms msg:"ok"
2024-03-08 14:31:05 [ERROR] user:bob ip:203.0.113.7 method:POST path:/api/login status:401 cost:120ms msg:"invalid password"
2024-03-08 14:33:41 [INFO] user:carol ip:198.51.100.23 method:GET path:/api/users/42 status:200 cost:18ms msg:"ok"
2024-03-08 14:35:12 [WARN] user:dave ip:192.168.1.66 method:DELETE path:/api/orders/7 status:403 cost:66ms msg:"forbidden"
2024-03-08 14:36:58 [ERROR] user:eve ip:203.0.113.99 method:GET path:/api/login status:500 cost:3005ms msg:"db timeout"
2024-03-08 14:32:00 [INFO] user:mallory ip:999.1.1.1 method:GET path:/api/x status:200 cost:5ms msg:"bad ip line"
2024-03-08 14:40:11 [INFO] user:oscar ip:192.168.1.5 method:PUT path:/api/orders/2024 status:200 cost:42ms msg:"say \\"hi\\""
"""
```

### 第一步：编写主解析模式

把"一行日志长什么样"翻译成模式。这里集中使用第 5—9 章的全部语法，并套用第 12 章的 `re.VERBOSE` 写注释版：

```python
import re
from collections import Counter
from datetime import datetime

log_pattern = re.compile(r"""
    ^                                        # 锚点：整行匹配（第 7 章）
    (?P<ts>\d{4}-\d{2}-\d{2}[ ]\d{2}:\d{2}:\d{2})   # 时间戳：预定义类+量词（第 6、8 章）
    \s+
    \[(?P<level>[A-Z]+)\]                    # 级别：字符类+量词（第 5、8 章）
    \s+
    user:(?P<user>\w+)                       # 用户名（注意 \w 的 Unicode 语义，第 6 章）
    \s+
    ip:(?P<ip>(?:25[0-5]|2[0-4]\d|1\d\d|[1-9]?\d)(?:\.(?:25[0-5]|2[0-4]\d|1\d\d|[1-9]?\d)){3})
                                             # IPv4：复用第 14.2 节，内部用 (?:) 避免多余捕获（第 9 章）
    \s+
    method:(?P<method>[A-Z]+)
    \s+
    path:(?P<path>/\S*)
    \s+
    status:(?P<status>\d{3})
    \s+
    cost:(?P<cost>\d+)ms
    \s+
    msg:"(?P<msg>(?:[^"\\]|\\.)*)"           # 引号字段：否定字符类+转义（第 5、14 章）
    $
""", re.VERBOSE)
```

**设计要点（逐个对应前面的知识点）**：

- **`^` 与 `$` 锚点**（第 7 章）：保证**整行**匹配。模式只认"完整的一行"，任何字段缺失或非法都会导致整行匹配失败——这正是容错的地基。
- **命名分组**（第 9.4 节）：7 个字段全部命名，后续用 `groupdict()` 一次性取回，无需数 `\1 \2` 的编号。
- **非捕获分组**（第 9.5 节）：IPv4 子模式内部全部用 `(?:...)`，避免产生一堆无用的捕获组。命名分组的编号不受影响，这里用 `(?:)` 是为了"不捕获无关内容"。
- **引号字段**：`msg:"(?:[^"\\]|\\.)*"` 是第 14.8 节"引号内文本"的升级版——`[^"\\]` 匹配普通字符，`\\.` 匹配"反斜杠+任意字符"（转义序列），两者交替，因此**能正确处理 `say \"hi\"` 这类含转义引号的内容**。
- **VERBOSE 陷阱（重要）**：`re.VERBOSE` 会忽略模式内**所有未转义空白**，所以时间戳里的字面空格必须写成 `[ ]`（字符类里只有一个空格），否则模式会变成 `\d{2}\d{2}` 而全部失配。这与第 12.2 节的提醒完全一致——本例就是它最典型的实战形态。

### 第二步：解析为结构化记录（match + 容错 + 语义校验）

逐行调用 `match`，配合模式自带的 `^...$` 锚点，**匹配失败的行直接跳过**（这就是需求 2 的容错实现）：

```python
records = []
skipped = []
for line in log_text.splitlines():
    m = log_pattern.match(line)          # 锚点整行匹配；match 从行首开始（第 7.4 节）
    if not m:
        skipped.append(line)             # 容错：坏行跳过，不影响后续解析
        continue
    d = m.groupdict()                    # 一次取回全部命名组（第 9.4 节）
    d["cost"] = int(d["cost"])           # 字符串 -> 数值
    d["status"] = int(d["status"])
    try:
        # 语义校验：正则只能查"格式"，查不出"2024-13-08"这种不存在的日期（第 14 章）
        d["ts"] = datetime.strptime(d["ts"], "%Y-%m-%d %H:%M:%S")
    except ValueError:
        d["ts"] = None
    records.append(d)
```

运行结果（与预期一致）：

```text
解析成功条数: 6  跳过条数: 1
  跳过: 2024-03-08 14:32:00 [INFO] user:mallory ip:999.1.1.1 method:GET path:/api/x status:200 cost:5ms msg:"bad ip line"

示例记录: {'ts': '2024-03-08 14:30:22', 'level': 'INFO', 'user': 'alice', 'ip': '192.168.1.10',
          'method': 'GET', 'path': '/api/orders/2024', 'status': 200, 'cost': 35, 'msg': 'ok'}
```

坏行 `ip:999.1.1.1` 因为 IPv4 子模式拒绝 `999` 而整体失配，被干净地跳过——**锚点 + 严格子模式 = 天然校验器**。

### 第三步：统计（正则的边界：只负责"取出来"）

字段已结构化，统计就是纯 Python 逻辑，不再需要任何正则：

```python
print("请求总数:", len(records))
print("按级别计数:", dict(Counter(r["level"] for r in records)))
avg = sum(r["cost"] for r in records) / len(records)
print("平均耗时: %.2f ms" % avg)
slowest = max(records, key=lambda r: r["cost"])
print("最慢请求: %s cost=%dms status=%d path=%s"
      % (slowest["user"], slowest["cost"], slowest["status"], slowest["path"]))
errors = [r for r in records if r["status"] >= 400]
print("错误请求数(4xx/5xx):", len(errors))
for r in errors:
    print("  %s %s %d" % (r["user"], r["path"], r["status"]))
```

```text
请求总数: 6
按级别计数: {'INFO': 3, 'ERROR': 2, 'WARN': 1}
平均耗时: 547.67 ms
最慢请求: eve cost=3005ms status=500 path=/api/login
错误请求数(4xx/5xx): 3
  bob /api/login 401
  dave /api/orders/7 403
  eve /api/login 500
```

> **工程原则**：正则的价值止步于"把非结构化文本变成结构化数据"。之后的聚合、比较、排序用语言自身完成——既快又不易错。

### 第四步：脱敏（sub + 函数替换 + 高级引号模式）

**IP 打码**：用命名分组捕获四个数字段，配合 `re.sub` 的**函数替换**（第 9.6 节），只保留首尾两段：

```python
masked = re.sub(
    r"(?P<a>\d+)\.(?P<b>\d+)\.(?P<c>\d+)\.(?P<d>\d+)",
    lambda m: f"{m.group('a')}.***.***.{m.group('d')}",
    log_text,
)
# 第一行结果：... ip:192.***.***.10 method:GET ...
```

**消息打码（先踩坑，再纠正）**：初学者最自然的写法是 `msg:"[^"]*"`（第 14.8 节的引号模式）。但遇到含转义引号的行（第 7 行），它会在**第一个引号处截断**：

```text
简单写法  msg:"[^"]*"              ->  ... msg:"***"hi\"      ← 残留了 hi\"
健壮写法  msg:"(?:[^"\\]|\\.)*"    ->  ... msg:"***"          ← 完整替换
```

原因：`[^"]*` 把转义引号 `\"` 里的 `"` 也当成了结束符。健壮版用 `\\.` 分支先吞掉 `\"`，就不会误判。**这正是第 14.8 节那条"高级引号模式"存在的理由。**

最终脱敏文本（节选第 1、6、7 行）：

```text
... ip:192.***.***.10 ... msg:"***"
... ip:999.***.***.1  ... msg:"***"      ← 坏行也被打码：脱敏正则只看"形状"不校验合法性
... ip:192.***.***.5  ... msg:"***"      ← 含转义引号的行被完整替换
```

### 第五步：零宽断言做"上下文提取"

最后演示第 11 章的知识在原始文本上的第二遍扫描。

**后顾提取**：`(?<=cost:)\d+` 与 `(?<=status:)\d{3}` 是定宽后顾，直接可用：

```python
re.findall(r"(?<=cost:)\d+", log_text)       # ['35','120','18','66','3005','5','42']
re.findall(r"(?<=status:)\d{3}", log_text)   # ['200','401','200','403','500','200','200']
```

> **注意**：结果里有 7 个值（含坏行 mallory 的 `5` 与 `200`）——断言只做**局部**检查，不做整行校验。需要整行语义时，回第一步用主模式。

**前后顾结合**：提取"消息为 ok 的请求"的状态码。后顾定位 `status:`，前瞻验证后续字段序列（前瞻无宽度限制，第 11.4 节）：

```python
re.findall(r'status:(?P<code>\d{3})(?=\s+cost:\d+ms\s+msg:"ok")', log_text)
# ['200', '200']   ← alice 与 carol 的两条 ok 请求
```

**变宽后顾的限制落地**：想直接"提取路径末尾的资源 ID"，写成 `(?<=path:/\w+/)\d+` 会**编译报错**——Python 要求后顾定宽，而 `\w+` 宽度不定：

```text
re.error: look-behind requires fixed-width pattern
```

正确做法：放弃后顾，改用**捕获组**（第 9 章）——`path:/\w+/\w+/(\d+)`：

```python
re.findall(r"path:/\w+/\w+/(\d+)", log_text)
# ['2024', '42', '7', '2024']   ← 两条 /api/orders/2024、一条 /api/users/42、一条 /api/orders/7
```

| 语义校验 | 正则 vs 专门库的分工（14 章） |
| 统计 | 正则边界：提取后交给语言（13、15 章最佳实践） |
| IP 脱敏 | `sub` + 函数替换 + 命名分组引用（9.6、13.5） |
| 消息脱敏 | 懒惰/否定字符类的局限与高级引号模式（8.2、14.8） |
| 上下文提取 | 定宽后顾、前瞻组合、变宽后顾限制与捕获组替代（11 章） |

### 案例小结：三个可迁移的工程原则

1. **先锚定整行，再提取字段**：`^...$`（或 `fullmatch`）让"一行是否合法"由引擎判定，坏数据天然被隔离，绝不产生半残记录。
2. **正则只做句法与提取，语义交给专门库**：格式用正则、日期与业务规则用 `datetime` 等库，各司其职。
3. **复杂模式必须"可读 + 可测"**：用 VERBOSE 注释、命名分组命名、先埋坏数据测试用例——本章模式的可维护性正来自这三条。

## 结语

正则表达式是一门 “上手快、精通难” 的语言：花半小时就能写出第一个可用的匹配模式，但即便耗费数年时间，也未必能吃透各个正则引擎之间的细节差异。对于初学者，比较稳妥的学习路径是：先吃透通用核心语法，动手练习基础匹配规则；再结合自己日常使用的编程语言，精读对应官方文档，了解引擎独有的特性与坑点；最后借助在线正则测试工具，反复校验自己的匹配逻辑，修正主观直觉带来的错误。熟练掌握简单正则，就足以大幅提升文本处理的工作效率；遇到极度复杂、晦涩的匹配场景，可以交给 AI 辅助完成即可。
