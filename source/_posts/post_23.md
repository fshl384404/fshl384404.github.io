## 编译程序概述

### 编译程序的任务

编译程序把用高级语言书写的源程序翻译为等价的低级语言程序。翻译过程需要完成三件事：识别源程序的结构，检查语义合法性，生成目标代码。若源程序存在错误，编译程序应报告错误的位置与原因。

编译程序与解释程序不同。编译程序一次把整个源程序翻译为目标程序，之后由目标程序独立运行；解释程序逐条读取源程序并立即执行，不生成独立的目标程序。编译程序的执行效率高，解释程序的交互性好。

### 编译过程的核心步骤

编译过程通常划分为以下阶段：

```text
源程序
  -> 词法分析
  -> 语法分析
  -> 语义分析
  -> 中间代码生成
  -> 代码优化
  -> 目标代码生成
  -> 目标程序
```

| 阶段 | 输入 | 输出 | 主要任务 |
| :--- | :--- | :--- | :--- |
| 词法分析 | 字符流 | 记号流 | 识别单词，过滤空白与注释 |
| 语法分析 | 记号流 | 语法树 | 检查语法结构，构造推导树 |
| 语义分析 | 语法树 | 带属性的语法树 | 类型检查、作用域解析、语义规则 |
| 中间代码生成 | 语法树 | 中间表示 | 转换为与机器无关的三地址码等 |
| 代码优化 | 中间代码 | 优化后的中间代码 | 减少计算量、存储访问与跳转 |
| 目标代码生成 | 中间代码 | 目标代码 | 指令选择、寄存器分配 |

词法分析与语法分析通常称为前端，目标代码生成与优化称为后端。前端的输出与源语言相关，后端的输出与目标机器相关。中间代码把前后端解耦，使同一个前端可以对接多个后端，同一个后端可以服务多种源语言。

### 符号表与错误处理

符号表贯穿整个编译过程，记录标识符的名称、类型、作用域、存储位置与其它属性。词法分析阶段插入标识符，语法分析阶段检查使用是否合法，语义分析阶段填写类型信息，代码生成阶段读取存储位置。

错误处理贯穿各个阶段。词法错误包括非法字符与未闭合字符串；语法错误包括缺少括号、运算符位置错误；语义错误包括类型不匹配、未声明变量、重复定义。编译器应尽量从错误中恢复，继续分析后续代码，而不是在第一个错误处终止。

## 词法分析

### 词法分析器的任务

词法分析器读取字符流，按词法规则识别出一个个记号（token），并过滤空白、换行与注释。记号的典型形式为：

$$\langle \text{token-name}, \text{attribute-value} \rangle$$

例如赋值语句：

```text
position = initial + rate * 60
```

可以识别为：

```text
<id, position> <assign> <id, initial> <plus> <id, rate> <times> <number, 60>
```

标识符的属性值通常指向符号表条目，数字的属性值是其数值。关键字通常在识别为标识符后查表区分，也可以直接由自动机识别。

词法分析器需要处理三个概念：

- **单词**：源程序中实际出现的字符串，如 `position`；
- **模式**：描述一类单词的形式，如标识符的正规表达式；
- **记号**：语法分析使用的最小单位，如 `id`。

词法分析采用最长匹配原则。例如 `if` 与 `iff` 都以 `if` 开头，遇到 `iff` 时应识别为标识符 `iff`，而不是关键字 `if` 后跟标识符 `f`。实现时通常需要向前查看一个字符。

### 正规表达式

正规表达式用于描述记号的模式。设字母表为 $\Sigma$，正规表达式的递归定义如下：

- $\varnothing$ 表示空集；
- $\varepsilon$ 表示只包含空串的集合；
- 对每个 $a \in \Sigma$，$a$ 表示只包含单字符 $a$ 的集合；
- 若 $r$ 与 $s$ 是正规表达式，则 $r \mid s$、$rs$、$r^*$ 也是正规表达式，分别表示并、连接与闭包。

运算符优先级从高到低为闭包、连接、并。括号可以改变结合顺序。

常见记号的模式如下：

| 记号 | 正规表达式 | 说明 |
| :--- | :--- | :--- |
| 标识符 | `[A-Za-z_][A-Za-z0-9_]*` | 字母或下划线开头 |
| 无符号整数 | `[0-9]+` | 一个或多个数字 |
| 浮点数 | `[0-9]+\.[0-9]+` | 简化形式 |
| 空白 | `[ \t\n]+` | 通常直接跳过 |
| 注释 | `//[^\n]*` | 行注释 |

正规表达式适合描述词法规则，但不适合描述嵌套结构。括号匹配、语句嵌套等需要上下文无关文法。

### 有限自动机

有限自动机是识别正规语言的数学模型。确定有限自动机（DFA）由五元组组成：

$$M = (Q, \Sigma, \delta, q_0, F)$$

其中 $Q$ 为状态集合，$\Sigma$ 为输入字母表，$\delta: Q \times \Sigma \to Q$ 为转移函数，$q_0$ 为初态，$F$ 为终态集合。DFA 在每个状态对每个输入字符都有唯一的下一状态。

非确定有限自动机（NFA）允许一个状态对同一输入字符有多个下一状态，也允许 $\varepsilon$ 转移。NFA 的转移函数形式为：

$$\delta: Q \times (\Sigma \cup \{\varepsilon\}) \to 2^Q$$

DFA 与 NFA 识别同一类语言，即正规语言。NFA 便于从正规表达式构造，DFA 便于高效执行。词法分析器通常先把正规表达式转换为 NFA，再转换为 DFA，最后生成状态转移表。

### 从正规表达式到 DFA

转换为三步：

1. **Thompson 构造**：把正规表达式转换为带 $\varepsilon$ 转移的 NFA。并、连接与闭包分别对应不同的子结构；
2. **子集构造**：用 $\varepsilon$-closure 与 move 操作把 NFA 转换为 DFA。DFA 的每个状态对应 NFA 状态集合；
3. **最小化**：合并等价状态，减少转移表规模。

以正规表达式 `(a|b)*abb` 为例，子集构造得到的 DFA 包含四个状态：

| 状态 | 含义 | 输入 a | 输入 b |
| :--- | :--- | :--- | :--- |
| A | 初始状态 | B | C |
| B | 已读入 a | B | D |
| C | 已读入 b | B | C |
| D | 已读入 abb | B | C |

其中 D 为终态。A 在读到 a 后进入 B，在读到 b 后进入 C；B 读到 b 后进入 D，表示已经匹配 `abb`；D 继续读入时回到 B 或 C，重新寻找下一次匹配。

子集构造的核心是 $\varepsilon$-closure。对状态集合 $T$，$\varepsilon$-closure(T) 是从 $T$ 出发只经过 $\varepsilon$ 转移可以到达的状态集合。对输入字符 $a$，move(T, a) 是从 $T$ 中某个状态经过 $a$ 转移可以到达的状态集合。

#### 子集构造过程

以 `(a|b)*abb` 为例，Thompson 构造得到的 NFA 包含状态 0 到 10：

```text
0 --ε--> 1, 7
1 --ε--> 2, 4
2 --a--> 3
4 --b--> 5
3 --ε--> 6
5 --ε--> 6
6 --ε--> 1, 7
7 --a--> 8
8 --b--> 9
9 --b--> 10
```

状态 10 为终态。初始状态的 ε-closure 为：

$$\varepsilon\text{-closure}(0) = \{0,1,2,4,7\}$$

记为 DFA 状态 A。对 A 中的状态求 a 的 move，再做 ε-closure，得到：

$$\text{move}(A,a) = \{3,8\}, \quad \varepsilon\text{-closure}(\{3,8\}) = \{1,2,3,4,6,7,8\}$$

记为 B。继续计算：

| DFA 状态 | NFA 状态集合 | 输入 a | 输入 b |
| :--- | :--- | :--- | :--- |
| A | {0,1,2,4,7} | B | C |
| B | {1,2,3,4,6,7,8} | B | D |
| C | {1,2,4,5,6,7} | B | C |
| D | {1,2,4,5,6,7,9} | B | C |

D 包含终态 10，因此 D 是 DFA 的终态。子集构造的关键是每次先求 move，再求 ε-closure，直到没有新的状态集合产生。

#### DFA 最小化

DFA 最小化把等价状态合并。初始划分把状态分为终态组与非终态组：

$$\{A,B,C\}, \{D\}$$

考察非终态组在输入 b 上的转移：A 转到 C，C 转到 C，B 转到 D。B 与 A、C 落入不同组，因此把 B 分出：

$$\{A,C\}, \{B\}, \{D\}$$

再考察 A 与 C：在输入 a 上都转到 B，在输入 b 上都转到 C，行为一致，可以合并。最小化后的 DFA 包含三个状态：AC、B、D。状态数减少，识别行为不变。

### 词法分析器的实现

词法分析器可以用状态转移表驱动：

```text
state = 0
while (state is not accepting or more input may extend match):
    c = next_char()
    state = table[state][c]
    append c to lexeme
return token corresponding to state
```

转移表的每一行对应一个状态，每一列对应一个输入字符。终态标记该状态对应的记号类型。最长匹配需要在终态后继续尝试，直到无法转移为止，再回退到最后一个终态。

实际实现中，关键字通常在识别为标识符后查关键字表；标识符插入符号表；数字转换为数值；空白与注释直接跳过。工具 Lex 与 Flex 根据正规表达式自动生成词法分析器，生成的核心就是上述转移表与驱动代码。
### 词法分析器生成器

Lex 与 Flex 根据正规表达式自动生成词法分析器。输入文件分为三部分：

```text
定义部分
%%
规则部分
%%
用户代码部分
```

规则部分每行由模式与动作组成：

```text
[0-9]+                  { return NUMBER; }
[a-zA-Z_][a-zA-Z0-9_]*  { return ID; }
[ \t\n]+               { /* 跳过空白 */ }
.                       { return yytext[0]; }
```

生成的扫描器按最长匹配选择规则；长度相同时，排在前面的规则优先。动作中的 `yytext` 指向匹配到的字符串，`yyleng` 是长度，`yylex()` 返回下一个记号。

Lex 在内部把正规表达式转换为 NFA，再转换为 DFA，最后生成状态转移表与驱动代码。手写词法分析器与生成器生成的扫描器在原理上一致，区别在于生成器把构造过程自动化。

## 语法分析

### 上下文无关文法

上下文无关文法（CFG）由四元组组成：

$$G = (V_T, V_N, S, P)$$

其中 $V_T$ 为终结符集合，$V_N$ 为非终结符集合，$S$ 为开始符号，$P$ 为产生式集合。产生式形式为 $A \to \alpha$，其中 $A \in V_N$，$\alpha \in (V_T \cup V_N)^*$。

以算术表达式为例：

```text
E -> E + T | T
T -> T * F | F
F -> ( E ) | id
```

该文法中 `E`、`T`、`F` 为非终结符，`+`、`*`、`(`、`)`、`id` 为终结符，`E` 为开始符号。产生式 `E -> E + T | T` 表示 `E` 可以推导出 `E + T` 或 `T`。

### 推导与语法树

从开始符号出发，反复用产生式右部替换左部的非终结符，最终得到终结符串，这一过程称为推导。每一步替换最左非终结符称为最左推导，替换最右非终结符称为最右推导。

语法树把推导过程表示为树：

- 根节点为开始符号；
- 内部节点为非终结符，子节点为产生式右部；
- 叶节点为终结符或 $\varepsilon$。

语法树忽略了推导顺序，只保留结构。同一棵语法树可能对应多种推导顺序，但最左推导与最右推导各自唯一。

如果同一个句子存在两棵不同的语法树，该文法称为二义文法。例如：

```text
E -> E + E | E * E | id
```

对 `id + id * id` 可以构造两种语法树，分别对应先加后乘与先乘后加。二义性会导致语义不唯一，需要通过优先级、结合性或文法改写消除。

改写后的表达式文法把优先级编码到层次中：`E` 处理加法，`T` 处理乘法，`F` 处理括号与原子。层次越低，优先级越高。

### 推导示例

以文法 `E -> E + T | T`、`T -> T * F | F`、`F -> ( E ) | id` 为例，`id + id * id` 的最左推导为：

```text
E => E + T
  => T + T
  => F + T
  => id + T
  => id + T * F
  => id + F * F
  => id + id * F
  => id + id * id
```

每一步替换当前句型中最左侧的非终结符。对应的语法树以 E 为根，左子树是 `id`，右子树是 `id * id`。右子树的乘法先于根节点的加法计算，体现了文法层次对优先级的编码。

### 递归下降分析法

递归下降分析法为每个非终结符编写一个函数，函数根据当前向前看符号选择产生式，并递归调用其它非终结符。

对于消除左递归后的表达式文法：

```text
E  -> T E'
E' -> + T E' | ε
T  -> F T'
T' -> * F T' | ε
F  -> ( E ) | id
```

递归下降的伪代码如下：

```text
parseE():
    parseT()
    parseEPrime()

parseEPrime():
    if lookahead == '+':
        match('+')
        parseT()
        parseEPrime()

parseT():
    parseF()
    parseTPrime()

parseTPrime():
    if lookahead == '*':
        match('*')
        parseF()
        parseTPrime()

parseF():
    if lookahead == '(':
        match('(')
        parseE()
        match(')')
    else if lookahead == id:
        match(id)
    else:
        error()
```

递归下降的优点是结构直观、易于手写、错误定位方便。局限是只能处理满足预测条件的文法，遇到左递归会无限递归，遇到公共前缀需要提取左公因子。

### 消除左递归与提取左公因子

左递归产生式：

```text
A -> A α | β
```

可以改写为：

```text
A  -> β A'
A' -> α A' | ε
```

直接左递归通过上述规则消除。间接左递归需要先代入展开，再按直接左递归处理。

公共前缀：

```text
A -> α β1 | α β2
```

改写为：

```text
A  -> α A'
A' -> β1 | β2
```

提取左公因子可以推迟选择，使向前看一个符号就能确定产生式。

### LL(1) 分析法

LL(1) 表示从左到右扫描输入，产生最左推导，向前看一个符号。LL(1) 分析法使用分析表，表的行是非终结符，列是终结符与结束符 `$`。

构造分析表需要 FIRST 与 FOLLOW 集合：

- FIRST(α) 是从 α 可以推导出的首终结符集合，若 α 可推导出 ε，则 ε 属于 FIRST(α)；
- FOLLOW(A) 是在某些句型中紧跟在 A 之后的终结符集合。

对产生式 $A \to \alpha$：

- 对每个 $a \in FIRST(\alpha)$，把 $A \to \alpha$ 填入 $M[A, a]$；
- 若 $\varepsilon \in FIRST(\alpha)$，对每个 $b \in FOLLOW(A)$，把 $A \to \alpha$ 填入 $M[A, b]$。

上述表达式文法的 FIRST 与 FOLLOW 如下：

| 非终结符 | FIRST | FOLLOW |
| :--- | :--- | :--- |
| E | `(`, `id` | `)`, `$` |
| E' | `+`, ε | `)`, `$` |
| T | `(`, `id` | `+`, `)`, `$` |
| T' | `*`, ε | `+`, `)`, `$` |
| F | `(`, `id` | `*`, `+`, `)`, `$` |

LL(1) 分析表如下：

| 非终结符 | `(` | `)` | `+` | `*` | `id` | `$` |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| E | E→TE' | | | | E→TE' | |
| E' | | E'→ε | E'→+TE' | | | E'→ε |
| T | T→FT' | | | | T→FT' | |
| T' | | T'→ε | T'→ε | T'→*FT' | | T'→ε |
| F | F→(E) | | | | F→id | |

若同一个表项填入多个产生式，则文法不是 LL(1)。左递归、公共前缀与二义性都会导致冲突。LL(1) 的优点是分析过程线性、实现简单；缺点是对文法限制较强，许多自然文法需要改写后才能使用。

### LL(1) 分析过程示例

以输入 `id + id * id` 为例，分析栈从 `$E` 开始，逐步展开非终结符：

| 步骤 | 栈（栈顶在右） | 输入 | 动作 |
| :-: | :--- | :--- | :--- |
| 1 | `$E` | `id + id * id $` | E→TE' |
| 2 | `$E'T` | `id + id * id $` | T→FT' |
| 3 | `$E'T'F` | `id + id * id $` | F→id |
| 4 | `$E'T'id` | `id + id * id $` | 匹配 id |
| 5 | `$E'T'` | `+ id * id $` | T'→ε |
| 6 | `$E'` | `+ id * id $` | E'→+TE' |
| 7 | `$E'T+` | `+ id * id $` | 匹配 + |
| 8 | `$E'T` | `id * id $` | T→FT' |
| 9 | `$E'T'F` | `id * id $` | F→id |
| 10 | `$E'T'id` | `id * id $` | 匹配 id |
| 11 | `$E'T'` | `* id $` | T'→*FT' |
| 12 | `$E'T'F*` | `* id $` | 匹配 * |
| 13 | `$E'T'F` | `id $` | F→id |
| 14 | `$E'T'id` | `id $` | 匹配 id |
| 15 | `$E'T'` | `$` | T'→ε |
| 16 | `$E'` | `$` | E'→ε |
| 17 | `$` | `$` | 接受 |

LL(1) 分析器只需查看栈顶非终结符与当前输入符号，就能在分析表中找到唯一产生式。若表中出现多个候选，文法不满足 LL(1)。

### 移进归约分析

移进归约分析使用栈保存已读入的符号，根据当前输入符号选择移进或归约：

- **移进**：把当前输入符号压入栈，读入下一个符号；
- **归约**：把栈顶与某个产生式右部匹配的符号串替换为该产生式左部；
- **接受**：栈中只剩开始符号且输入结束；
- **出错**：无法移进也无法归约。

以表达式文法分析 `id + id * id`：

| 步骤 | 栈 | 输入 | 动作 |
| :-: | :--- | :--- | :--- |
| 0 | `$` | `id + id * id $` | 移进 |
| 1 | `$ id` | `+ id * id $` | 归约 F→id |
| 2 | `$ F` | `+ id * id $` | 归约 T→F |
| 3 | `$ T` | `+ id * id $` | 归约 E→T |
| 4 | `$ E` | `+ id * id $` | 移进 + |
| 5 | `$ E +` | `id * id $` | 移进 id |
| 6 | `$ E + id` | `* id $` | 归约 F→id |
| 7 | `$ E + F` | `* id $` | 归约 T→F |
| 8 | `$ E + T` | `* id $` | 移进 * |
| 9 | `$ E + T *` | `id $` | 移进 id |
| 10 | `$ E + T * id` | `$` | 归约 F→id |
| 11 | `$ E + T * F` | `$` | 归约 T→T*F |
| 12 | `$ E + T` | `$` | 归约 E→E+T |
| 13 | `$ E` | `$` | 接受 |

移进归约的关键是确定何时归约。句柄是当前句型中与某个产生式右部匹配、且归约后仍能得到正确推导的子串。LR 分析器通过状态与向前看符号精确判断句柄。

### LR 分析器

LR 分析器由分析栈、状态转移表与动作表组成。状态表示已经识别到产生式的哪个位置。LR 项（item）用圆点标记位置，例如：

```text
A -> α · β
```

表示产生式 $A \to \alpha\beta$ 中，$\alpha$ 已经识别，接下来期待 $\beta$。

LR(0) 项集通过闭包与转移构造：

- **闭包**：若项 $A \to \alpha \cdot B \beta$ 在集合中，则对所有产生式 $B \to \gamma$，把 $B \to \cdot \gamma$ 加入集合；
- **转移**：对项集 $I$ 与符号 $X$，goto(I, X) 是闭包中包含 $A \to \alpha X \cdot \beta$ 的项集，其中 $A \to \alpha \cdot X \beta \in I$。

以文法为例：

```text
S' -> S
S  -> a A
A  -> b
```

LR(0) 项集与转移如下：

```text
I0: S' -> ·S, S -> ·aA
I1: S' -> S·                 (接受)
I2: S -> a·A, A -> ·b
I3: A -> b·
I4: S -> aA·
```

转移关系为：

```text
I0 --S--> I1
I0 --a--> I2
I2 --A--> I4
I2 --b--> I3
```

对应的动作：

- I0 遇到 `a` 移进到 I2；
- I2 遇到 `b` 移进到 I3；
- I3 归约 A→b；
- I4 归约 S→aA；
- I1 接受。

### SLR 分析表

仍以文法 `S' -> S`、`S -> a A`、`A -> b` 为例，FOLLOW(S) = {`$`}，FOLLOW(A) = {`$`}。SLR 分析表如下：

| 状态 | a | b | $ | S | A |
| :-: | :--- | :--- | :--- | :--- | :--- |
| 0 | s2 | | | 1 | |
| 1 | | | acc | | |
| 2 | | s3 | | | 4 |
| 3 | | | r(A→b) | | |
| 4 | | | r(S→aA) | | |

表中 s 表示移进，r 表示归约，acc 表示接受，数字表示目标状态。分析 `a b` 时，状态 0 遇到 a 移进到 2，状态 2 遇到 b 移进到 3，状态 3 在 `$` 上归约 A→b，回到状态 2 后转到 4，状态 4 归约 S→aA，最后接受。

### SLR、LR(1) 与 LALR

LR(0) 在归约时不看向前看符号，容易产生冲突。SLR(1) 在归约时检查向前看符号是否属于 FOLLOW(A)，减少了冲突。

LR(1) 项带有向前看符号：

```text
[A -> α · β, a]
```

表示在识别到 α 后，只有向前看符号为 a 时才按该产生式归约。LR(1) 的分析能力强于 SLR(1)，但状态数量多。

LALR(1) 把具有相同 LR(0) 核心的 LR(1) 状态合并，减少状态数量。LALR(1) 的分析能力介于 SLR(1) 与 LR(1) 之间，可能引入归约归约冲突，但不会引入移进归约冲突。多数实用分析器生成器使用 LALR(1)。

存在这样的文法：它是 LR(1) 的，但不是 SLR(1) 的。例如：

```text
S -> C C
C -> c C | d
```

该文法在 SLR(1) 下会产生移进归约冲突，在 LR(1) 下可以正确区分。选择分析器类型时，需要根据文法规模与冲突情况权衡状态数量与分析能力。

### LR(1) 项的向前看符号

LR(1) 项在 LR(0) 项的基础上增加向前看符号：

```text
[A -> α · β, a]
```

表示在识别到 α 后，只有当前输入符号为 a 时，才按 A→αβ 归约。向前看符号缩小了归约的适用范围，减少了冲突。

以文法 `S -> C C`、`C -> c C | d` 为例，SLR 在归约 C→d 时只检查 FOLLOW(C) = {c, d, $}，无法区分当前上下文；LR(1) 项会携带具体的向前看符号，把不同上下文中的 C→d 区分开。该文法是 LR(1) 的，但不是 SLR(1) 的。

LALR(1) 把具有相同 LR(0) 核心的 LR(1) 状态合并，状态数量接近 SLR，分析能力接近 LR(1)。合并可能引入归约归约冲突，但不会引入移进归约冲突。

### 语法错误的恢复

语法分析器发现错误后，可以采用以下恢复策略：

- **恐慌模式**：跳过输入符号，直到遇到同步记号，如分号、右括号或语句关键字；
- **短语级恢复**：对常见错误做局部修正，如插入缺失的括号或分号；
- **错误产生式**：在文法中加入专门处理错误的产生式，捕获特定错误模式；
- **全局校正**：寻找使输入合法的最近修改序列，计算代价较高，实际使用较少。

错误恢复的目标是继续分析后续代码，尽可能报告多个错误，而不是在第一个错误处终止。
### 语法分析器生成器

Yacc 与 Bison 根据上下文无关文法生成 LALR(1) 分析器。规则部分为每个产生式附加语义动作：

```text
%token NUMBER
%left '+'
%left '*'

%%
expr : expr '+' term   { $$ = $1 + $3; }
     | term            { $$ = $1; }
     ;

term : term '*' factor { $$ = $1 * $3; }
     | factor          { $$ = $1; }
     ;

factor : '(' expr ')'  { $$ = $2; }
       | NUMBER        { $$ = $1; }
       ;
%%
```

`$$` 表示左部非终结符的语义值，`$1`、`$2` 表示右部各符号的语义值。`%left` 声明运算符的结合性与优先级，用于消解移进归约冲突。生成器构造 LALR(1) 分析表，冲突无法消解时报告给用户。

语法分析器生成器把文法转换为分析表，开发者只需编写产生式与语义动作。与手写递归下降相比，生成器适合文法较大、需要频繁修改的场景；手写递归下降更适合错误恢复与控制流定制。

## 语义分析

### 语法制导定义

语法制导定义（Syntax-Directed Definition，SDD）为每个产生式关联一组语义规则，用属性描述语法成分的值、类型或其它信息。属性分为两类：

- **综合属性**：由子节点的属性计算得到，沿语法树自底向上传递；
- **继承属性**：由父节点或左兄弟的属性计算得到，沿语法树自顶向下或从左向右传递。

只含综合属性的 SDD 称为 S 属性定义，可以在自底向上的分析过程中计算。含继承属性的 SDD 需要规定计算顺序，通常要求属性依赖不形成环。

以表达式求值为例：

```text
E -> E1 + T    { E.val = E1.val + T.val }
E -> T         { E.val = T.val }
T -> T1 * F    { T.val = T1.val * F.val }
T -> F         { T.val = F.val }
F -> ( E )     { F.val = E.val }
F -> digit     { F.val = digit.lexval }
```

`val` 是综合属性，父节点的值由子节点计算得到。对 `2 + 3 * 4`，语法树自底向上计算，得到 14。

继承属性的典型例子是变量声明：

```text
D -> T L       { L.inh = T.type }
T -> int       { T.type = integer }
T -> real      { T.type = real }
L -> L1 , id   { L1.inh = L.inh; addtype(id.entry, L.inh) }
L -> id        { addtype(id.entry, L.inh) }
```

`L.inh` 把声明类型从 `T` 传给标识符列表，使每个标识符获得正确的类型。继承属性无法在普通的自底向上分析中直接计算，需要在分析过程中按依赖顺序求值。

### 属性求值示例

以 `2 + 3 * 4` 为例，按综合属性自底向上求值：

| 节点 | 产生式 | 子节点值 | 计算结果 |
| :--- | :--- | :--- | :--- |
| F(2) | F→digit | lexval=2 | val=2 |
| T(2) | T→F | F.val=2 | val=2 |
| E(2) | E→T | T.val=2 | val=2 |
| F(3) | F→digit | lexval=3 | val=3 |
| T(3) | T→F | F.val=3 | val=3 |
| F(4) | F→digit | lexval=4 | val=4 |
| T(12) | T→T*F | 3, 4 | val=12 |
| E(14) | E→E+T | 2, 12 | val=14 |

综合属性的值只依赖子节点，因此可以按后序遍历计算。继承属性的值依赖父节点或左兄弟，需要按前序或从左到右的顺序计算。

### 语法制导翻译

语法制导翻译（Syntax-Directed Translation，SDT）把语义动作嵌入产生式，在分析过程中执行。动作可以放在产生式右部的任意位置，执行时机由位置决定。

```text
E -> E1 + T    { E.val = E1.val + T.val }
```

动作放在产生式末尾时，在右部符号全部识别后执行，适合自底向上的分析。动作放在中间时，在对应位置执行，适合自顶向下的分析，但需要保证动作不会引用尚未计算的属性。

SDT 可以直接生成中间代码。例如把表达式翻译为三地址码：

```text
E -> E1 + T    { E.addr = newtemp(); emit(E.addr "=" E1.addr "+" T.addr) }
```

`newtemp()` 生成临时变量，`emit()` 输出一条三地址指令。语法树与语义动作结合，可以在一次遍历中完成类型检查与代码生成。

### 类型检查

类型检查验证程序中的运算与赋值是否符合类型规则。类型系统通常包括：

- **基本类型**：整数、实数、布尔、字符；
- **构造类型**：数组、记录、指针、函数；
- **类型表达式**：用类型构造符组合基本类型；
- **类型环境**：记录标识符到类型的映射。

类型检查可以在编译期完成（静态类型），也可以在运行期完成（动态类型）。静态类型检查能提前发现错误，但需要类型声明与类型推断；动态类型检查灵活，但错误发现较晚。

类型等价分为名称等价与结构等价。名称等价要求类型名相同，结构等价要求类型结构相同。类型转换分为隐式转换与显式转换，隐式转换由编译器插入，显式转换由程序员书写。

### 类型检查示例

考虑声明与赋值：

```text
int x;
real y;
x = y + 1;
```

`y` 的类型为 real，`1` 的类型为 int。按类型规则，real 与 int 相加的结果为 real。把 real 赋给 int 变量时，强类型语言会报类型错误；允许隐式转换的语言会插入取整操作，可能丢失小数部分。

类型检查需要类型环境记录标识符的类型，并对每个表达式推导类型。数组下标要求整数类型，指针解引用要求指针类型，函数调用要求实参类型与形参类型匹配。类型错误应在编译期报告，避免运行期出现未定义行为。

### 语义分析中的声明处理

声明处理把标识符及其类型写入符号表。以 `int x; real y;` 为例，符号表条目如下：

| 名称 | 种类 | 类型 | 作用域 | 偏移量 |
| :--- | :--- | :--- | :--- | :--- |
| x | 变量 | int | 全局 | 0 |
| y | 变量 | real | 全局 | 4 |

进入代码块时创建新的作用域，声明写入当前作用域；退出代码块时弹出作用域，内层声明不再可见。查找标识符时从当前作用域向外层逐级查找，避免内层变量遮蔽外层变量时取错条目。

声明处理还需要检查重复定义、类型合法性以及初始化表达式。例如 `int x = 1.5;` 在强类型语言中应报错，在允许隐式转换的语言中会插入取整操作。数组声明需要计算元素类型、维数与总大小，函数声明需要记录参数类型与返回类型。

### 中间语言

中间语言位于源语言与目标语言之间，目的是把前端与后端解耦。常见形式包括：

- **抽象语法树（AST）**：保留程序的层次结构，便于分析与变换；
- **三地址码**：每条指令最多包含三个操作数，形式简单，便于优化与代码生成；
- **四元式**：用四个字段表示一条三地址指令；
- **三元式**：用三个字段表示指令，结果用指令序号引用；
- **静态单赋值形式（SSA）**：每个变量只赋值一次，便于数据流分析与优化。

以 `a = b + c * d` 为例，三地址码为：

```text
t1 = c * d
t2 = b + t1
a = t2
```

对应的四元式为：

```text
( * , c , d , t1 )
( + , b , t1 , t2 )
( = , t2 , _ , a )
```

对应的三元式为：

```text
0: ( * , c , d )
1: ( + , b , (0) )
2: ( = , (1) , a )
```

三地址码的指令类型包括赋值、算术运算、逻辑运算、无条件跳转、条件跳转、过程调用、数组访问与指针访问。控制流语句可以翻译为标号与跳转：

```text
if (a < b) x = 1; else x = 2;
```

翻译为：

```text
t1 = a < b
ifFalse t1 goto L1
x = 1
goto L2
L1: x = 2
L2:
```

## 中间代码生成

中间代码生成把语法树或 SDT 的动作序列转换为中间表示。主要工作包括：

- 为表达式生成临时变量与三地址指令；
- 为控制流生成标号与跳转；
- 为函数调用生成参数传递与返回指令；
- 为数组与记录生成地址计算；
- 为变量声明分配存储位置。

布尔表达式的翻译需要处理短路求值。`a && b` 在 `a` 为假时不再计算 `b`，`a || b` 在 `a` 为真时不再计算 `b`。翻译时使用回填技术，先生成跳转指令并留空目标标号，待目标确定后再回填。

### 控制流与数组的中间代码

`while` 循环可以翻译为标号与条件跳转：

```text
while (a < b) { x = x + 1; }
```

```text
L1: t1 = a < b
    ifFalse t1 goto L2
    t2 = x + 1
    x = t2
    goto L1
L2:
```

数组访问需要计算元素地址。假设每个元素占 4 字节，`x = a[i]` 翻译为：

```text
t1 = i * 4
t2 = a + t1
x = *t2
```

数组赋值 `a[i] = x` 翻译为：

```text
t1 = i * 4
t2 = a + t1
*t2 = x
```

多维数组按行优先展开，地址计算需要把各维下标乘以对应的步长后累加。结构体字段访问则在基地址上加字段偏移。

## 代码优化

代码优化在不改变程序语义的前提下改善目标代码的质量。优化分为与机器无关的优化和与机器相关的优化。

常见优化包括：

| 优化 | 作用 | 示例 |
| :--- | :--- | :--- |
| 常量折叠 | 在编译期计算常量表达式 | `x = 2 * 3 + a` 变为 `x = 6 + a` |
| 常量传播 | 用常量替换已知取值的变量 | `x = 5; y = x + 1` 变为 `y = 6` |
| 复写传播 | 用原变量替换复制的变量 | `t = x; y = t + 1` 变为 `y = x + 1` |
| 公共子表达式消除 | 复用已计算的结果 | 两次 `c * d` 只计算一次 |
| 死代码消除 | 删除不影响结果的代码 | 删除不可达分支与未使用赋值 |
| 强度削弱 | 用廉价运算替代昂贵运算 | 乘法改为移位或加法 |
| 循环不变代码外提 | 把循环中不变的表达式移到循环外 | 循环内的 `a * b` 只计算一次 |
| 循环展开 | 减少循环控制开销 | 一次迭代处理多个元素 |

优化通常在基本块与控制流图上进行。基本块是顺序执行、只有一个入口与一个出口的指令序列；控制流图用节点表示基本块，用边表示跳转关系。数据流分析用于判断变量在某个程序点的可达定义、活跃性与常量值。

### 基本块与数据流示例

基本块是顺序执行、只有一个入口与一个出口的指令序列。考虑：

```text
x = 1
y = 2
z = x + y
if z > 0 goto L1
w = 0
goto L2
L1: w = z
L2: ...
```

前三条指令构成一个基本块，`if` 之后分成两个分支，各自构成基本块。常量传播把 `x=1`、`y=2` 代入 `z=x+y`，常量折叠得到 `z=3`。若 `z` 在后续只用于条件判断，还可以进一步简化分支。

数据流分析在控制流图上计算每个程序点的可达定义、活跃变量与常量值。到达定值分析用于常量传播与复写传播，活跃变量分析用于死代码消除与寄存器分配。

### 优化实例

考虑循环：

```text
for (i = 0; i < n; i++) {
    a[i] = a[i] + b * 2;
}
```

`b * 2` 在循环中不随 `i` 变化，可以外提到循环外：

```text
t = b * 2;
for (i = 0; i < n; i++) {
    a[i] = a[i] + t;
}
```

数组地址 `a + i * 4` 中的乘法可以改为每次迭代加 4 的加法，属于强度削弱。循环结束后不再使用的临时变量可以删除，属于死代码消除。

基本块内的优化更局部。例如：

```text
x = 2
y = 3
z = x * y
```

常量传播与折叠后直接得到 `z = 6`。若 `x`、`y` 之后不再使用，相关赋值可以删除。优化的前提是不能改变程序的可观察行为，包括异常、输入输出与副作用。

## 目标代码生成

目标代码生成把中间代码转换为目标机器的指令序列。主要任务包括：

- **指令选择**：为每条中间指令选择合适的机器指令；
- **寄存器分配**：把变量分配到寄存器或内存，常用图着色算法；
- **指令调度**：调整指令顺序，减少流水线停顿。

寄存器分配把变量视为图的节点，若两个变量在同一时刻活跃，则在它们之间连边。用 $k$ 种颜色对图着色，每种颜色对应一个寄存器。无法着色的变量溢出到内存，在需要时加载到寄存器。

目标代码生成需要了解目标机器的指令集、寻址方式、寄存器数量与流水线特性。同一段中间代码在不同机器上的最优指令序列可能不同。

### 指令选择示例

三地址码 `t1 = b + c` 可以翻译为：

```text
LOAD  R1, b
ADD   R1, c
STORE t1, R1
```

若目标机器支持内存操作数，可以合并为：

```text
LOAD  R1, b
ADD   R1, [c]
STORE t1, R1
```

指令选择需要在指令数量、寻址方式与执行周期之间权衡。寄存器分配决定哪些变量留在寄存器、哪些溢出到内存。指令调度在不改变语义的前提下调整顺序，减少流水线停顿。

### 寄存器分配实例

考虑三地址码：

```text
t1 = a + b
t2 = c + d
t3 = t1 * t2
t4 = t3 - t1
```

在 `t3 = t1 * t2` 处，t1 与 t2 同时活跃；在 `t4 = t3 - t1` 处，t1 与 t3 同时活跃。干扰图包含边 t1-t2、t1-t3、t2-t3，三个变量两两冲突。

若只有两个寄存器，干扰图无法用两种颜色着色，需要把一个变量溢出到内存。例如把 t2 溢出：计算 t3 前把 t2 装入寄存器，计算后再释放。溢出增加了访存指令，但保证了寄存器数量约束下的正确性。

图着色算法先删除度数小于寄存器数的节点，压入栈；若剩余节点都无法删除，选择一个节点标记为溢出；然后按栈逆序着色。溢出节点在每次使用前重新装入，使用后写回。

## 符号表

符号表记录标识符的属性，是编译过程中多个阶段共享的数据结构。常见实现是哈希表，每个桶保存一个标识符链表或开放寻址。

符号表的主要操作包括：

- **插入**：在词法或语法分析阶段登记标识符；
- **查找**：在语义分析与代码生成阶段查询属性；
- **进入作用域**：创建新的作用域；
- **退出作用域**：删除或隐藏当前作用域的标识符。

作用域通常用栈管理。进入块时压入新的作用域，退出块时弹出。查找时从最内层作用域向外层查找，直到找到标识符或到达全局作用域。

符号表条目通常包含名称、种类、类型、存储类别、作用域层次、偏移量与其它属性。代码生成阶段根据偏移量计算变量的地址，调试信息则记录源代码行号与变量名的对应关系。

### 作用域示例

考虑嵌套作用域：

```text
int x;
{
    int x;
    x = 1;
}
x = 2;
```

符号表为外层 `x` 与内层 `x` 分别建立条目。进入代码块时压入新的作用域，内层 `x` 遮蔽外层 `x`；退出代码块时弹出内层作用域，外层 `x` 重新可见。查找时从当前作用域向外层逐级查找，直到找到第一个匹配条目。

符号表通常与语法树节点关联。声明节点保存符号表条目指针，引用节点在语义分析时填入类型与存储位置，代码生成阶段直接读取这些信息。

## 结语

编译过程把源程序逐步转换为目标程序。词法分析识别单词，语法分析建立结构，语义分析检查含义，中间代码生成把程序转换为统一的中间表示，优化改善代码质量，目标代码生成完成机器相关的翻译。

词法分析的核心是正规表达式与有限自动机，语法分析的核心是文法、推导与分析方法，语义分析的核心是属性文法与语法制导翻译。三者构成编译原理的主干。中间代码、优化、目标代码与符号表服务于工程实现，理解其基本作用即可，细节可以在具体编译器中查阅。
