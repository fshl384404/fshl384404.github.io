## 计算机系统的层次结构

### 从硬件到应用

计算机系统由硬件与软件共同构成。硬件提供可执行的指令与数据通路，软件把具体问题转换为硬件可以执行的操作。二者之间通过指令集体系结构连接：硬件实现指令集，软件在指令集之上分层构建。

从下到上，计算机系统可以划分为若干机器级：

| 层次 | 名称 | 主要内容 |
| :--- | :--- | :--- |
| M0 | 微程序机器级 | 微指令与微程序，直接控制硬件 |
| M1 | 传统机器级 | 机器指令集，由微程序或硬布线实现 |
| M2 | 操作系统机器级 | 进程、内存、设备与文件管理 |
| M3 | 汇编语言级 | 用助记符表示机器指令 |
| M4 | 高级语言级 | C、Java、Python 等语言及其编译系统 |
| M5 | 应用语言级 | 面向特定领域的语言与工具 |

低层是高层的基础，高层通过翻译或解释在低层实现。编译程序把高级语言翻译为机器语言，解释程序逐条执行高级语言语句。层次划分的意义在于把复杂性分层管理：每一层只需了解相邻层的接口，不必掌握所有底层细节。

### 冯·诺依曼结构

冯·诺依曼结构确立了现代计算机的基本组织方式，其核心思想是存储程序：

- 计算机由运算器、控制器、存储器、输入设备与输出设备五大部分组成；
- 程序与数据以二进制形式存放在同一存储器中；
- 指令由操作码与地址码组成，按顺序存放与执行；
- 控制器按程序计数器取出指令，译码后发出控制信号；
- 运算器完成算术与逻辑运算，输入输出设备负责与外界交换数据。

存储程序使计算机可以通过修改程序改变功能，而不需要改动硬件。这一特性是通用计算机的基础。

冯·诺依曼结构也带来了固有瓶颈：指令与数据共享同一总线，取指与取数不能同时进行；CPU 与存储器之间的速度差距随处理器发展不断扩大。现代计算机通过 Cache、多级存储、指令流水线与分离的指令与数据 Cache 缓解这一瓶颈，但基本组织方式仍然沿用。

### 程序执行步骤

一条指令的执行通常包含以下阶段：

1. **取指**：程序计数器给出指令地址，控制器从存储器读取指令，程序计数器更新；
2. **译码**：指令译码器分析操作码，确定操作类型与寻址方式；
3. **取操作数**：根据地址码计算有效地址，从寄存器或存储器读取操作数；
4. **执行**：运算器完成算术、逻辑或移位操作，或由控制器完成转移；
5. **访存**：需要写回存储器时，把结果写入指定地址；
6. **写回**：把结果写回寄存器；
7. **中断检查**：指令结束后检查是否有中断请求，有则进入中断响应。

上述阶段构成指令周期。指令周期可进一步划分为机器周期与时钟周期。不同指令的机器周期数不同，复杂指令需要多次访存与多次运算。

### 硬件性能指标

| 指标 | 含义 | 说明 |
| :--- | :--- | :--- |
| 字长 | CPU 一次处理的二进制位数 | 影响运算精度与寻址范围 |
| 主频 | 时钟信号的频率 | 主频越高，单周期时间越短 |
| CPI | 每条指令平均时钟周期数 | 与指令集、流水线、Cache 命中率相关 |
| MIPS | 每秒执行百万条指令 | 适合比较同类指令集 |
| FLOPS | 每秒浮点运算次数 | 衡量科学计算能力 |
| 存储容量 | 主存与辅存的容量 | 主存容量影响可运行程序规模 |
| 存储带宽 | 单位时间传输的数据量 | 由总线宽度与频率决定 |
| MTBF | 平均无故障时间 | 衡量系统可靠性 |

CPU 执行时间可以表示为：

$$T = \frac{IC \times CPI}{f}$$

其中 $IC$ 为指令条数，$CPI$ 为平均时钟周期数，$f$ 为主频。提高性能可以从减少指令条数、降低 CPI、提高主频三个方向入手，三者之间往往存在取舍。

### 指令执行示例

以 `ADD R1, [addr]` 为例，指令把内存单元的内容加到寄存器 R1。执行过程可以分解为若干微操作：

```text
取指：
  PC -> MAR
  M(MAR) -> MDR
  MDR -> IR
  PC + 1 -> PC

译码与取操作数：
  IR 的地址字段 -> MAR
  M(MAR) -> MDR

执行：
  R1 + MDR -> R1
```

取指阶段所有指令都要执行，译码与执行阶段由指令类型决定。控制器根据操作码发出相应的控制信号，数据通路在各部件之间传递数据。指令执行结束后检查中断请求，若有中断则进入中断周期。

### 性能计算示例

设程序包含 $10^9$ 条指令，平均 CPI 为 1.5，主频为 3 GHz，则执行时间为：

$$T = \frac{10^9 \times 1.5}{3 \times 10^9} = 0.5\text{s}$$

对应的 MIPS 为：

$$\text{MIPS} = \frac{f}{CPI \times 10^6} = \frac{3000}{1.5} = 2000$$

若通过优化把 CPI 降到 1.2，执行时间降为 0.4s，性能提升 25%。若主频提高到 4 GHz 而 CPI 不变，执行时间降为 0.375s。主频提升往往伴随 CPI 上升，实际收益需要综合评估。

### 控制器与数据通路

控制器根据指令产生控制信号，数据通路在控制信号下完成数据传递与运算。控制器有两种典型实现：

| 实现方式 | 原理 | 优点 | 缺点 |
| :--- | :--- | :--- | :--- |
| 硬布线控制 | 用组合逻辑直接产生控制信号 | 速度快，适合简单指令集 | 设计复杂，修改困难 |
| 微程序控制 | 把控制信号编成微指令存放在控制存储器中 | 设计规整，易于扩展 | 需要读取微指令，速度较慢 |

微程序控制把一条机器指令分解为若干微指令，微程序计数器给出下一条微指令的地址，微指令的各个字段直接控制数据通路。硬布线控制用译码器与逻辑门产生控制信号，速度快但缺乏灵活性。

数据通路由寄存器、ALU、总线与多路选择器组成。寄存器存放操作数与中间结果，ALU 完成算术与逻辑运算，多路选择器选择数据来源，内部总线连接各部件。指令的执行过程就是控制信号驱动数据在数据通路中流动的过程。

CISC 指令集复杂，单条指令可以完成较多操作，适合微程序控制；RISC 指令集简单规整，便于流水线与硬布线控制。现代处理器通常在内部把复杂指令拆分为微操作，兼顾兼容性与执行效率。

## 系统总线

### 基本概念

总线是连接多个部件、用于传输信息的一组共享信号线。总线把处理器、存储器与 I/O 设备连接起来，使它们可以交换地址、数据与控制信号。

总线由若干信号线组成，按功能分为三类：

- **数据总线**：传输数据，宽度决定一次传输的位数；
- **地址总线**：传输地址，宽度决定可寻址空间；
- **控制总线**：传输读写命令、中断请求、总线请求与响应等控制信号。

总线是共享资源，同一时刻只能有一个主设备发起传输。多个设备争用总线时，需要总线仲裁决定使用权。

### 总线分类

| 分类方式 | 类型 | 说明 |
| :--- | :--- | :--- |
| 按位置 | 片内总线、系统总线、通信总线 | 芯片内部、计算机内部、设备之间 |
| 按信号 | 数据总线、地址总线、控制总线 | 按传输的信息类型划分 |
| 按传输方式 | 并行总线、串行总线 | 同时传输多位或逐位传输 |
| 按定时方式 | 同步总线、异步总线 | 由统一时钟或握手信号控制 |
| 按方向 | 单向总线、双向总线 | 信号只能单向或可双向传输 |

现代计算机的内部互连逐渐从共享并行总线转向点对点串行链路。PCI Express 使用多条串行通道，每条通道独立传输，避免了并行总线的时钟偏移与争用问题。

### 总线特性

总线规范通常规定四个方面的特性：

- **机械特性**：接口形状、引脚数量与排列、插头尺寸；
- **电气特性**：信号电平、驱动能力、传输方向与阻抗；
- **功能特性**：每根信号线的功能，如地址、数据、读写控制；
- **时间特性**：信号的有效时刻、持续时间与时序关系。

总线规范保证不同厂商的设备可以互换。设备只要满足机械、电气、功能与时间特性，就可以接入同一总线。

### 性能指标

总线的主要性能指标包括：

- **总线宽度**：数据线的位数，常见为 32 位、64 位；
- **总线频率**：时钟频率，单位为 MHz 或 GHz；
- **传输速率**：单位时间传输的字节数；
- **总线周期**：一次完整传输所需的时间。

对于每个时钟周期传输一次的总线，带宽为：

$$B = \frac{W}{8} \times f$$

其中 $W$ 为数据线位数，$f$ 为时钟频率，$B$ 的单位为字节每秒。若总线在时钟上升沿与下降沿各传输一次，带宽翻倍。

例如，数据线宽度为 32 位、时钟频率为 100 MHz、每周期传输一次，则带宽为 $4 \times 100\text{M} = 400\text{MB/s}$。

### 总线架构

常见总线架构包括：

- **单总线结构**：CPU、主存与 I/O 设备共用一组总线。结构简单，但所有传输争用同一总线，带宽有限。
- **双总线结构**：CPU 与主存之间使用高速存储总线，CPU 与 I/O 之间使用 I/O 总线。存储访问与 I/O 传输可以部分并行。
- **三总线结构**：增加 DMA 总线，使外设与主存之间可以直接传输，减轻 CPU 与系统总线的负担。

现代计算机通常采用层次化互连：CPU 与内存通过高速链路连接，外设通过 PCIe 与芯片组连接，芯片组再连接存储与低速外设。共享总线仍然存在于片内与设备内部，但系统级互连更多采用点对点结构。

### 总线控制

总线控制分为仲裁与通信控制两部分。

**总线仲裁**决定多个主设备争用总线时谁先使用。常见方式如下：

| 方式 | 原理 | 特点 |
| :--- | :--- | :--- |
| 链式查询 | 总线授权信号沿设备链依次传递 | 结构简单，优先级固定，靠近控制器的设备优先 |
| 计数器定时查询 | 控制器发出设备号，逐次计数匹配 | 优先级可调整，控制线较少 |
| 独立请求 | 每个设备有独立的请求与授权线 | 响应快，优先级灵活，线数多 |

**通信控制**决定数据传输的时序。同步总线使用统一时钟，主设备在固定时刻发出命令，从设备在固定时刻返回数据。同步控制简单，但要求所有设备满足最慢设备的时序。

异步总线使用握手信号，主设备发出请求，从设备返回应答。异步控制适应不同速度的设备，按握手方式分为：

- **不互锁**：请求与应答各自保持固定时间，不等待对方；
- **半互锁**：请求等待应答，应答不等待请求撤销；
- **全互锁**：请求与应答互相等待，可靠性最高，速度最慢。

同步总线适合高速、设备速度相近的场景；异步总线适合速度差异大、传输距离较远的场景。
### 总线传输时序

同步总线使用统一时钟。一次读传输通常包含以下步骤：

1. CPU 在地址线上给出地址，并在控制线上发出读信号；
2. 存储器在下一个时钟周期译码地址，把数据放到数据线上；
3. CPU 在约定的时钟边沿采样数据；
4. 传输结束，地址与控制信号撤销。

若存储器来不及在约定周期内返回数据，可以插入等待周期。等待周期通过等待信号通知 CPU 延长当前总线周期。等待周期越多，总线带宽越低。

### 带宽计算示例

数据线 32 位、时钟 100 MHz、每个传输需要 2 个等待周期时，一次传输占用 3 个时钟周期：

$$B = \frac{4\text{B} \times 100\text{M}}{3} \approx 133\text{MB/s}$$

若采用突发传输，一次地址阶段后连续传输 4 个数据，地址开销被分摊，带宽接近 $4\text{B} \times 100\text{M} = 400\text{MB/s}$ 的理论上限。突发长度越长，地址开销占比越低。

### 总线仲裁示例

三个设备共用一条总线，采用链式查询。总线控制器发出授权信号，信号沿设备链依次传递。设备 1 靠近控制器，若它请求总线，授权信号在设备 1 处被截获，设备 2 与设备 3 收不到授权。设备 1 不请求时，授权信号继续传向设备 2。

链式查询的优先级由物理位置决定，靠近控制器的设备优先级最高。优点是控制线少、实现简单；缺点是不可灵活调整优先级，且某一设备故障可能影响后续设备。

### 总线结构实例

单总线结构把所有部件连接到同一组总线：

```text
CPU ----+---- 主存
        |
      I/O 设备
```

单总线结构简单，但 CPU 访存与 I/O 传输争用同一总线，带宽有限。

双总线结构把存储总线与 I/O 总线分开：

```text
CPU ==== 主存
 |
 +---- I/O 总线 ---- 设备
```

CPU 与主存之间的高速传输不占用 I/O 总线，I/O 传输可以与存储访问部分并行。

三总线结构增加 DMA 总线，使外设与主存可以直接传输：

```text
CPU ==== 主存
 |         |
 +-- I/O --+
      |
    DMA 总线 ---- 高速外设
```

现代计算机使用点对点互连替代共享总线。CPU 通过高速链路连接内存控制器与 PCIe 根复合体，外设通过独立通道连接，避免所有设备争用同一组信号线。

## 存储器

### 存储层次与局部性

计算机的存储系统按速度、容量与成本分为多个层次：

| 层次 | 典型介质 | 访问时间 | 容量 | 作用 |
| :--- | :--- | :--- | :--- | :--- |
| 寄存器 | 触发器 | 约 1 个时钟周期 | 几十到几百字节 | 存放当前指令与操作数 |
| Cache | SRAM | 几个到几十个时钟周期 | 几十 KB 到几十 MB | 缓存主存中的热点数据 |
| 主存 | DRAM | 几十到几百个时钟周期 | GB 级 | 存放运行中的程序与数据 |
| 辅存 | SSD、磁盘 | 微秒到毫秒 | TB 级 | 长期保存数据 |

层次结构依赖程序访问的局部性。时间局部性指刚访问过的数据很可能再次访问，例如循环中的计数器与累加变量；空间局部性指相邻地址的数据很可能连续访问，例如数组遍历与顺序执行的指令。

Cache 利用局部性把主存中的热点数据复制到高速介质。设命中率为 $h$，Cache 访问时间为 $T_c$，主存访问时间为 $T_m$，平均访问时间可以写为：

$$T = h T_c + (1-h)(T_c + T_m) = T_c + (1-h)T_m$$

该式假设缺失时先访问 Cache 再访问主存，且 $T_m$ 表示缺失代价。若 Cache 与主存并行访问，公式需要按实际时序调整。

### 主存储器

主存由存储阵列、地址译码、读写控制与数据缓冲组成。按存储元件分为 SRAM 与 DRAM：

| 类型 | 存储元件 | 特点 | 用途 |
| :--- | :--- | :--- | :--- |
| SRAM | 双稳态触发器 | 速度快、无需刷新、集成度低、成本高 | Cache |
| DRAM | 电容 | 速度较慢、需要刷新、集成度高、成本低 | 主存 |

DRAM 用电容存储电荷，电荷会泄漏，因此需要定期刷新。刷新按行进行，常见方式包括集中刷新、分散刷新与异步刷新。刷新操作占用存储周期，但不需要 CPU 干预。

DRAM 芯片的地址线通常复用：行地址与列地址分时送入，分别由 RAS 与 CAS 信号锁存。地址复用减少了引脚数量，代价是访问需要两个步骤。

主存容量扩展分为位扩展与字扩展：

- **位扩展**：增加数据线宽度。例如用 8 位芯片组成 32 位字长，需要 4 片并联，地址线共用，数据线分别连接 32 位数据总线的不同部分。
- **字扩展**：增加存储单元数量。例如用 16K×8 位芯片组成 64K×8 位存储空间，需要 4 组芯片，通过高位地址译码选择芯片。

用 16K×8 位芯片组成 64K×32 位存储器，需要 4 片完成位扩展，再复制 4 组完成字扩展，共 16 片。64K 地址需要 16 根地址线，其中低 14 位连接芯片地址端，高 2 位经 2-4 译码器产生 4 组片选信号。

多模块存储器可以进一步提高带宽。低位交叉编址把连续地址分配到不同模块，连续访问时各模块可以并行工作；高位交叉编址把地址空间按模块划分，适合扩容但不一定提高连续访问带宽。

### 存储芯片扩展实例

用 16K×8 位芯片组成 64K×32 位存储器时，地址空间划分为四组，每组 16K：

| 组号 | 地址范围 | 片选信号 |
| :-: | :--- | :--- |
| 0 | 0x0000 到 0x3FFF | CS0 |
| 1 | 0x4000 到 0x7FFF | CS1 |
| 2 | 0x8000 到 0xBFFF | CS2 |
| 3 | 0xC000 到 0xFFFF | CS3 |

地址线 A0 到 A13 连接所有芯片的地址端，A14 与 A15 送入 2-4 译码器，译码输出分别作为四组的片选信号。每组内部有 4 片芯片并行工作，数据线分别连接 D0-D7、D8-D15、D16-D23、D24-D31，实现 32 位字长。

访问地址 0x5A3C 时，A15A14 = 01，选中第 1 组；组内偏移为 0x1A3C，由 A0-A13 寻址。四片芯片同时输出 32 位数据，CPU 一次读取完整字。

### Cache 的基本结构

Cache 由若干行组成，每行包含数据块、标记、有效位，写回策略还需要脏位。主存与 Cache 之间以块为单位交换数据，块大小通常为 32 字节、64 字节或 128 字节。

一次访问的过程如下：

1. CPU 给出主存地址；
2. 地址被拆分为标记、索引与块内偏移；
3. 用索引定位到 Cache 行或组；
4. 比较标记与有效位；
5. 标记匹配且有效位为 1 时命中，按偏移取出数据；
6. 未命中时从主存读取整个块，放入 Cache，再返回所需数据。

Cache 的容量、块大小与相联度共同决定地址划分。块越大，空间局部性利用越充分，但缺失代价与冲突概率也越高；块越小，标记开销越大。

### Cache 与主存的映射

映射方式决定主存块可以放入哪些 Cache 行。常见方式有直接映射、全相联映射与组相联映射。

#### 直接映射

直接映射把主存块固定映射到唯一的 Cache 行：

$$\text{行号} = \text{主存块号} \bmod \text{Cache 行数}$$

主存地址划分为标记、行号与块内偏移：

```text
| 标记 tag | 行号 line | 块内偏移 offset |
```

以 32 位地址、64 KB Cache、64 字节块为例：

- Cache 行数为 $64\text{KB} / 64\text{B} = 1024$；
- 块内偏移为 $\log_2 64 = 6$ 位；
- 行号为 $\log_2 1024 = 10$ 位；
- 标记为 $32 - 6 - 10 = 16$ 位。

主存块 0、1024、2048 都映射到行 0。若程序交替访问这三个块，每次访问都会覆盖上一块，产生冲突缺失。这种反复覆盖同一行的现象称为抖动。

直接映射的优点是硬件简单，只需一个标记比较器，查找速度快。缺点是对冲突敏感，命中率受地址分布影响较大。

#### 全相联映射

全相联映射允许主存块放入任意 Cache 行：

```text
| 标记 tag | 块内偏移 offset |
```

以上述 64 KB Cache、64 字节块为例，块内偏移 6 位，标记 26 位。查找时需要把标记与所有 1024 行的标记并行比较。

全相联没有冲突缺失，命中率高于直接映射。代价是比较器数量多、硬件成本高，通常只用于小容量 Cache，例如 TLB 与一级指令 Cache。

#### 组相联映射

组相联映射把 Cache 分为若干组，每组包含若干行（路）。主存块固定映射到某一组，但可以放入组内任意一行：

$$\text{组号} = \text{主存块号} \bmod \text{组数}$$

地址划分为标记、组号与块内偏移：

```text
| 标记 tag | 组号 set | 块内偏移 offset |
```

以 32 位地址、4 路组相联、1024 组、64 字节块为例：

- 块内偏移 6 位；
- 组号 10 位；
- 标记 16 位；
- 总容量为 $1024 \times 4 \times 64 = 256\text{KB}$。

查找时先用组号定位组，再并行比较组内 4 路的标记。组相联在冲突率与硬件成本之间取得平衡，是现代处理器最常用的结构。

三种映射方式的对比：

| 方式 | 地址划分 | 查找方式 | 冲突缺失 | 硬件成本 |
| :--- | :--- | :--- | :--- | :--- |
| 直接映射 | 标记、行号、偏移 | 一个比较器 | 高 | 低 |
| 全相联 | 标记、偏移 | 全部标记并行比较 | 无 | 高 |
| 组相联 | 标记、组号、偏移 | 组内多路并行比较 | 中 | 中 |

### 替换算法

直接映射无需替换。全相联与组相联在组内满时需要选择被替换的行。常见算法包括：

- **随机替换**：随机选择一行，硬件简单，命中率一般；
- **先进先出（FIFO）**：替换最早进入的行，不考虑访问频率；
- **最近最少使用（LRU）**：替换最久未访问的行，符合时间局部性，命中率较高；
- **最不经常使用（LFU）**：替换访问次数最少的行，需要计数器。

LRU 需要记录每行的访问顺序，硬件开销较大。实际处理器常用近似 LRU，例如为每行维护一位或几位使用信息。

以 2 路组相联、2 组、块地址序列 0、1、2、0、3、0、1、4 为例，组号为块地址模 2，采用 LRU 替换：

| 访问 | 组 | 结果 | 替换 | 组内容（最近使用在前） |
| :-: | :-: | :--- | :--- | :--- |
| 0 | 0 | 缺失 | 无 | 0 |
| 1 | 1 | 缺失 | 无 | 1 |
| 2 | 0 | 缺失 | 无 | 2, 0 |
| 0 | 0 | 命中 | 无 | 0, 2 |
| 3 | 1 | 缺失 | 无 | 3, 1 |
| 0 | 0 | 命中 | 无 | 0, 2 |
| 1 | 1 | 命中 | 无 | 1, 3 |
| 4 | 0 | 缺失 | 2 | 4, 0 |

8 次访问中命中 3 次，命中率为 37.5%。若采用 FIFO，替换顺序不同，命中率可能变化。

### 写策略

写操作需要同时考虑 Cache 与主存的一致性。常见策略如下：

| 策略 | 做法 | 优点 | 缺点 |
| :--- | :--- | :--- | :--- |
| 写直达 | 同时写 Cache 与主存 | 主存始终最新，控制简单 | 写操作开销大 |
| 写回 | 只写 Cache，置脏位，替换时写回主存 | 减少主存写次数 | 需要脏位，控制复杂 |

写缺失时有两种处理方式：

- **写分配**：先把块读入 Cache，再执行写操作，适合写回策略；
- **非写分配**：直接写主存，不把块读入 Cache，适合写直达策略。

写直达可以配合写缓冲，CPU 把写数据放入缓冲区后继续执行，由缓冲区异步写入主存。写回在替换脏行时才写主存，带宽利用率高，但一致性维护更复杂。

### 性能分析

Cache 的性能由命中率、命中时间与缺失代价共同决定。平均访存时间（AMAT）为：

$$\text{AMAT} = T_c + (1-h)T_m$$

其中 $T_c$ 为命中时间，$T_m$ 为缺失代价，$h$ 为命中率。

例如 $T_c = 1\text{ns}$，$T_m = 100\text{ns}$，$h = 0.95$，则：

$$\text{AMAT} = 1 + 0.05 \times 100 = 6\text{ns}$$

相比直接访问主存的 100ns，平均访问时间缩短到 6ns。命中率从 95% 提高到 99% 时，AMAT 降为 2ns，说明高命中率区间的收益非常显著。

多级 Cache 的 AMAT 可以逐级计算：

$$\text{AMAT} = T_1 + m_1(T_2 + m_2 T_3 + \cdots)$$

其中 $m_1$ 为 L1 缺失率，$m_2$ 为 L2 局部缺失率。例如 L1 命中时间 1ns、缺失率 5%，L2 命中时间 10ns、局部缺失率 20%，主存 100ns，则：

$$\text{AMAT} = 1 + 0.05 \times (10 + 0.2 \times 100) = 2.5\text{ns}$$

### 写策略示例

设 Cache 采用写回策略，初始时块 X 不在 Cache 中。依次执行两次写 X，随后块 X 被替换：

| 操作 | Cache 状态 | 主存状态 | 说明 |
| :--- | :--- | :--- | :--- |
| 第一次写 X | 缺失，写分配读入 X，修改后置脏位 | 旧值 | 写命中后只改 Cache |
| 第二次写 X | 命中，修改后保持脏位 | 旧值 | 主存仍未更新 |
| X 被替换 | 脏块写回主存 | 新值 | 替换时一次性写回 |

若采用写直达，两次写 X 都会同时更新主存，替换时不需要写回。写直达的实现简单，但每次写都产生主存访问；写回把多次写合并为一次写回，带宽利用率更高。

### 映射计算实例

以 32 位地址 `0x1234A5C0` 为例，二进制为：

```text
0001 0010 0011 0100 1010 0101 1100 0000
```

对 64 字节块，块内偏移为低 6 位：

```text
offset = 0x1234A5C0 & 0x3F = 0
```

对 1024 行或 1024 组的 Cache，索引为地址的第 6 到第 15 位：

```text
index = (0x1234A5C0 >> 6) & 0x3FF = 0x297 = 663
```

标记为高 16 位：

```text
tag = 0x1234A5C0 >> 16 = 0x1234
```

因此该地址在直接映射 Cache 中访问第 663 行，标记为 0x1234；在 4 路组相联 Cache 中访问第 663 组，组内 4 路并行比较标记；在全相联 Cache 中只需比较 26 位标记。

### 缺失类型

Cache 缺失分为三类：

- **强制性缺失**：块第一次被访问，Cache 中必然没有该块；
- **容量缺失**：Cache 容量不足，块被替换后再次访问；
- **冲突缺失**：Cache 仍有空闲行，但映射规则限制了块的放置位置。

直接映射的冲突缺失最明显。主存块 0、1024、2048 都映射到行 0，即使 Cache 其它行空闲，交替访问这三个块仍会反复缺失。组相联通过增加路数减少冲突缺失，全相联则完全消除冲突缺失。

### 多级 Cache 与一致性

现代处理器通常有三级 Cache：L1 分为指令 Cache 与数据 Cache，L2 为统一 Cache，L3 由多个核共享。L1 追求低延迟，容量较小；L3 追求容量与命中率，延迟较高。

多级 Cache 可以采用包含式或非包含式关系。包含式要求 L2 包含 L1 的全部内容，便于一致性检查；非包含式允许各级独立，容量利用率更高。

多核系统中，每个核有私有 Cache，缓存一致性成为问题。监听式协议通过总线监听失效或更新，目录式协议通过目录记录共享状态。常见状态包括修改、独占、共享与无效。

### 辅助存储器

磁盘由盘片、磁头、磁道与扇区组成。磁盘访问时间包括：

$$T = T_{seek} + T_{rotation} + T_{transfer}$$

寻道时间是把磁头移动到目标磁道的时间，旋转延迟是等待目标扇区转到磁头下方的时间，传输时间是读写数据的时间。平均旋转延迟为半圈时间。以 7200 转/分的磁盘为例，每圈约 8.33ms，平均旋转延迟约 4.17ms。若寻道时间为 8ms、传输时间为 0.5ms，平均访问时间约为 12.67ms。

固态硬盘使用闪存颗粒，没有机械运动，随机读写延迟远低于磁盘。闪存的擦除次数有限，需要通过磨损均衡、垃圾回收与地址映射延长寿命。SSD 的写入放大与垃圾回收会影响长期性能。

RAID 把多个磁盘组合为逻辑单元，常见级别如下：

| 级别 | 技术 | 特点 |
| :--- | :--- | :--- |
| RAID 0 | 条带化 | 容量与性能提升，无冗余 |
| RAID 1 | 镜像 | 可靠性高，容量利用率 50% |
| RAID 5 | 分布式奇偶校验 | 允许一块盘故障，容量利用率高 |
| RAID 6 | 双奇偶校验 | 允许两块盘故障，写入开销更大 |
| RAID 10 | 镜像加条带 | 性能与可靠性兼顾，成本高 |

## 输入输出系统

### I/O 设备与接口

I/O 设备按数据单位分为字符设备与块设备。字符设备以字节流为单位，如键盘、串口；块设备以数据块为单位，如磁盘、SSD。设备速度差异很大，键盘每秒几十字节，磁盘每秒数百 MB，CPU 与设备之间需要接口进行缓冲与速度匹配。

I/O 接口通常包含：

- **数据寄存器**：暂存传输的数据；
- **状态寄存器**：表示设备忙、就绪、错误等状态；
- **控制寄存器**：接收 CPU 发出的启动、停止、读写命令；
- **地址译码**：识别 CPU 访问的是哪个寄存器；
- **中断控制**：向 CPU 发出中断请求。

接口的作用是把设备的具体时序转换为总线可以接受的时序，使 CPU 不必了解设备的内部细节。CPU 访问 I/O 寄存器有两种方式：独立编址为 I/O 端口分配独立的地址空间，使用专门的 I/O 指令；统一编址把 I/O 寄存器映射到内存地址空间，使用普通的访存指令。统一编址的指令简单，但占用内存地址空间。

### 程序查询方式

程序查询方式由 CPU 主动读取设备状态，循环等待设备就绪：

```text
CPU 发出启动命令
  -> 读取状态寄存器
  -> 设备未就绪则继续读取
  -> 设备就绪后传输一个数据
  -> 继续下一个数据
```

这种方式硬件简单，但 CPU 在等待期间不能执行其他任务。设备越慢，CPU 浪费越多。程序查询适合设备速度较快或 CPU 没有其他任务可执行的场景。

程序查询的效率可以用 CPU 等待时间占总时间的比例衡量。若设备传输一个字节需要 1ms，CPU 查询与传输只需要 1μs，则 CPU 有 99.9% 的时间在等待。对慢速设备使用程序查询会严重浪费处理器资源。

### 中断方式

中断方式由设备在就绪或完成时主动通知 CPU。CPU 执行完当前指令后检查中断请求，若允许响应，则保存现场并转入中断服务程序。

中断处理的关键概念包括：

- **中断请求**：设备置位中断请求信号；
- **中断屏蔽**：CPU 通过中断允许位控制是否响应；
- **中断优先级**：多个设备同时请求时，按优先级决定响应顺序；
- **中断向量**：中断服务程序的入口地址；
- **中断嵌套**：高优先级中断可以打断低优先级中断的服务程序；
- **现场保护与恢复**：保存程序计数器与寄存器，处理完成后恢复。

一次中断处理的流程如下：

```text
设备发出中断请求
  -> CPU 完成当前指令
  -> 检查中断允许位与优先级
  -> 保存程序计数器与程序状态字
  -> 根据中断向量转入服务程序
  -> 保存通用寄存器
  -> 处理设备请求
  -> 恢复寄存器
  -> 返回原程序继续执行
```

中断向量表保存各类中断的服务程序入口。CPU 收到中断后，根据中断类型号查表得到入口地址。优先级高的中断可以打断优先级低的服务程序，形成中断嵌套；处理嵌套时需要保证现场保存与恢复的顺序正确。

中断方式使 CPU 在设备工作期间可以执行其他任务，提高了利用率。代价是每次传输都需要一次中断响应，频繁的小数据量传输会产生较大的上下文切换开销。中断更适合随机事件与中低速设备，例如键盘输入与网络数据到达。

### DMA 方式

DMA（Direct Memory Access）方式由 DMA 控制器在外设与主存之间直接传输数据，CPU 只在传输开始与结束时参与。

传输过程如下：

1. CPU 初始化 DMA 控制器，设置源地址、目的地址、传输长度与方向；
2. DMA 控制器向总线仲裁器请求总线使用权；
3. 获得总线后，DMA 控制器直接在主存与设备之间传输数据；
4. 传输完成后，DMA 控制器向 CPU 发出中断；
5. CPU 检查状态并处理后续工作。

DMA 与 CPU 争用总线。常见方式包括：

| 方式 | 做法 | 对 CPU 的影响 |
| :--- | :--- | :--- |
| 停止 CPU 访存 | DMA 独占总线，成块传输 | CPU 暂停访存，传输快 |
| 周期挪用 | 每个存储周期结束后占用一个周期 | CPU 访存被延迟，影响较小 |
| 透明 DMA | 利用 CPU 不访存的空闲周期 | 对 CPU 几乎无影响，控制复杂 |

DMA 适合高速块设备与大批量传输。传输过程中 CPU 不参与数据搬运，只负责初始化与结束处理，因此效率高于中断方式。DMA 的代价是增加 DMA 控制器与总线仲裁逻辑，且需要处理 Cache 一致性问题：若 DMA 直接写主存，Cache 中的旧数据可能失效，需要由硬件或软件维护一致性。

### 中断处理实例

以键盘输入为例。用户按下按键，键盘控制器把扫描码放入数据寄存器，并置位中断请求。CPU 完成当前指令后响应中断：

1. 保存程序计数器与程序状态字；
2. 根据中断类型号查中断向量表，得到服务程序入口；
3. 转入键盘中断服务程序，保存通用寄存器；
4. 从键盘数据端口读取扫描码，转换为键值并放入输入缓冲区；
5. 向中断控制器发送结束信号；
6. 恢复寄存器与现场，返回原程序。

中断向量表把中断类型号映射到入口地址。不同设备可以共享同一中断线，由操作系统在服务程序中进一步判断来源。中断嵌套时，高优先级中断可以打断低优先级服务程序，保存与恢复现场必须按栈的顺序进行。

### DMA 传输示例

设磁盘向主存传输 4 KB 数据，DMA 控制器以 4 字节为单位传输，共需 1024 次传输。若每次占用一个 100ns 的存储周期，总线占用时间为：

$$1024 \times 100\text{ns} = 102.4\mu\text{s}$$

CPU 只在初始化 DMA 控制器与传输结束中断时参与，开销约为几微秒。若改用程序查询，每个字都需要执行取状态、判断、传送、修改地址等多条指令，CPU 开销会高出数个数量级。DMA 的优势在大块数据传输时尤为明显。

### 中断优先级与嵌套示例

设三个设备的中断优先级为 A 高于 B、B 高于 C。若 A 与 B 同时请求，CPU 先响应 A；若 C 在 A 的服务程序执行期间请求，C 的优先级低于 A，必须等待；若 B 在 A 的服务程序执行期间请求，B 的优先级高于 A，可以打断 A，形成中断嵌套。

处理顺序如下：

```text
A 请求 -> 响应 A，进入 A 的服务程序
B 请求 -> 打断 A，进入 B 的服务程序
B 完成 -> 返回 A 的服务程序
A 完成 -> 返回主程序
C 请求 -> 响应 C
```

中断嵌套要求每个服务程序在进入时保存现场、退出时恢复现场。优先级高的中断可以打断优先级低的服务程序，反之不行。中断屏蔽字可以进一步控制哪些中断允许嵌套，避免关键区段被高优先级中断破坏。

### 通道方式

通道方式进一步把 I/O 控制从 CPU 中分离，由通道处理器执行通道程序，管理多台设备。CPU 只需发出 I/O 指令，通道独立完成数据传输并在结束时中断 CPU。通道方式适合大型机与高吞吐存储系统，现代个人计算机更多使用 DMA 与设备控制器。

### 三种 I/O 方式的对比

| 方式 | CPU 参与程度 | 数据通路 | 适用场景 |
| :--- | :--- | :--- | :--- |
| 程序查询 | 全程参与，循环等待 | CPU 与设备之间 | 低速设备、简单系统 |
| 中断 | 每次传输参与一次 | CPU 与设备之间 | 中低速设备、随机事件 |
| DMA | 开始与结束参与 | 设备与主存之间 | 高速块设备、大批量传输 |

## 计算机的运算方法

### 无符号数与有符号数

无符号数把全部二进制位用于表示数值。$n$ 位无符号数的范围为：

$$0 \le x \le 2^n - 1$$

8 位无符号数的范围为 0 到 255。无符号数适合表示地址、计数与长度等不可能为负的量。

有符号数需要留出一位表示符号。常见表示方法包括原码、反码、补码与移码：

| 表示法 | 正数 | 负数 | 8 位范围 | 零的个数 |
| :--- | :--- | :--- | :--- | :--- |
| 原码 | 符号位 0，数值位为绝对值 | 符号位 1，数值位为绝对值 | -127 到 127 | 2 |
| 反码 | 与原码相同 | 数值位按位取反 | -127 到 127 | 2 |
| 补码 | 与原码相同 | 反码加 1 | -128 到 127 | 1 |
| 移码 | 补码符号位取反 | 补码符号位取反 | -128 到 127 | 1 |

补码是现代计算机的标准表示。它把减法统一为加法，零只有一种表示，符号位可以直接参与运算。$n$ 位补码的范围为：

$$-2^{n-1} \le x \le 2^{n-1} - 1$$

8 位补码的范围为 -128 到 127。最小负数 -128 没有对应的正数，这是补码范围不对称的原因。

### 补码加减运算

补码加法按位相加，丢弃最高位的进位。减法转换为加上减数的补码：

$$A - B = A + (-B) = A + \bar{B} + 1$$

以 8 位为例，计算 $5 + 3$：

```text
  0000 0101   (5)
+ 0000 0011   (3)
-----------
  0000 1000   (8)
```

计算 $5 - 3$，即 $5 + (-3)$。-3 的补码为 1111 1101：

```text
  0000 0101   (5)
+ 1111 1101   (-3)
-----------
1 0000 0010   (2，丢弃最高位进位)
```

计算 $127 + 1$：

```text
  0111 1111   (127)
+ 0000 0001   (1)
-----------
  1000 0000   (-128，溢出)
```

两个正数相加得到负数，说明发生溢出。计算 $-128 - 1$：

```text
  1000 0000   (-128)
+ 1111 1111   (-1)
-----------
1 0111 1111   (127，溢出)
```

两个负数相加得到正数，同样说明溢出。

溢出判断规则如下：

- 两个同号数相加，结果的符号与操作数不同，则溢出；
- 两个异号数相减，结果的符号与预期不同，则溢出；
- 从进位角度，符号位的进位输入与进位输出不同，则溢出，即 $V = C_{in} \oplus C_{out}$。

### 定点乘法与除法

定点数的小数点位置固定。定点整数的小数点位于最低位之后，定点小数的小数点位于符号位与数值位之间。

无符号乘法采用移位相加。以 4 位无符号数 $3 \times 5$ 为例，被乘数为 0011，乘数为 0101：

```text
乘数最低位为 1，部分积加 0011
乘数右移，被乘数左移
下一位为 0，部分积不变
下一位为 1，部分积加 1100
得到 1111，即 15
```

有符号乘法需要处理符号位。Booth 算法通过编码乘数相邻两位，把连续 1 的加法转换为加法与减法，减少部分积数量。Booth 算法适合补码表示，硬件实现广泛。

定点除法采用移位相减。恢复余数法从被除数高位开始，每次左移一位并与除数比较，够减则商位为 1，不够减则商位为 0 并恢复余数。加减交替法根据余数符号决定下一步加还是减，减少恢复操作。

定点运算的优点是硬件简单、速度快；缺点是可表示的数值范围有限，容易溢出。科学计算与图形处理通常使用浮点数。

### 乘法实例

以 4 位无符号数 $3 \times 5$ 为例，被乘数为 0011，乘数为 0101。移位相加的过程可以简化为：

| 步骤 | 乘数当前位 | 操作 | 累加结果 |
| :-: | :-: | :--- | :--- |
| 1 | 1 | 加 0011 | 0011 |
| 2 | 0 | 不加 | 0011 |
| 3 | 1 | 加 1100 | 1111 |
| 4 | 结束 | 不移位 | 1111 |

结果为 1111，即 15。实际硬件使用双倍字长的累加器与移位寄存器，逐位处理乘数，避免中间结果溢出。

### 浮点表示

浮点数由符号、阶码与尾数组成：

$$x = (-1)^S \times M \times 2^E$$

其中 $S$ 为符号位，$M$ 为尾数，$E$ 为阶码。IEEE 754 标准定义了单精度与双精度格式：

| 格式 | 符号位 | 阶码位 | 尾数位 | 偏移量 | 有效精度 |
| :--- | :-: | :-: | :-: | :-: | :--- |
| 单精度 | 1 | 8 | 23 | 127 | 约 7 位十进制 |
| 双精度 | 1 | 11 | 52 | 1023 | 约 15 到 17 位十进制 |

规格化数的尾数隐含最高位 1，实际尾数为 $1.F$。阶码采用偏移表示，单精度的实际阶码为 $E - 127$，双精度为 $E - 1023$。

以 13.25 为例：

```text
13.25 = 1101.01
      = 1.10101 × 2^3
符号位 S = 0
阶码 E = 3 + 127 = 130 = 1000 0010
尾数 F = 1010 1000 0000 0000 0000 000
```

拼接后得到：

```text
0 10000010 10101000000000000000000
= 0100 0001 0101 0100 0000 0000 0000 0000
= 0x41540000
```

以 -0.15625 为例：

```text
0.15625 = 0.00101
        = 1.01 × 2^-3
符号位 S = 1
阶码 E = -3 + 127 = 124 = 0111 1100
尾数 F = 0100 0000 0000 0000 0000 000
```

拼接后得到：

```text
1 01111100 01000000000000000000000
= 1011 1110 0010 0000 0000 0000 0000 0000
= 0xBE200000
```

IEEE 754 还定义了特殊值：

| 阶码 | 尾数 | 含义 |
| :--- | :--- | :--- |
| 全 0 | 全 0 | 正零或负零 |
| 全 0 | 非 0 | 非规格化数 |
| 全 1 | 全 0 | 正无穷或负无穷 |
| 全 1 | 非 0 | NaN |

非规格化数用于表示接近零的极小值，牺牲有效位数换取更小的表示范围。NaN 表示未定义或无效的运算结果，例如 0 除以 0。

单精度与双精度的表示范围如下：

| 格式 | 最大规格化数 | 最小规格化数 | 最小非规格化数 |
| :--- | :--- | :--- | :--- |
| 单精度 | 约 $3.4 \times 10^{38}$ | 约 $1.18 \times 10^{-38}$ | 约 $1.4 \times 10^{-45}$ |
| 双精度 | 约 $1.8 \times 10^{308}$ | 约 $2.23 \times 10^{-308}$ | 约 $4.9 \times 10^{-324}$ |

### 浮点运算

浮点加减法的步骤为：

1. **对阶**：把阶码较小的操作数尾数右移，直到两个数的阶码相同。右移时保留附加位，避免精度损失；
2. **尾数加减**：对阶后的尾数按定点运算加减；
3. **规格化**：结果尾数不在 $[1,2)$ 范围内时，左移或右移并调整阶码；
4. **舍入**：按选定方式舍入到目标精度；
5. **溢出判断**：阶码超出范围时，判定为上溢或下溢。

以 $1.5 + 0.25$ 为例：

```text
1.5  = 1.1   × 2^0
0.25 = 1.0   × 2^-2
对阶：0.25 = 0.01 × 2^0
相加：1.10 + 0.01 = 1.11
结果：1.11 × 2^0 = 1.75
```

再以 $1.5 + (-1.25)$ 为例：

```text
1.5   =  1.10 × 2^0
-1.25 = -1.01 × 2^0
阶码相同，直接相减：1.10 - 1.01 = 0.01
规格化：0.01 = 1.0 × 2^-2
结果：0.25
```

结果为 0.25。若两个操作数阶码不同，需要先对阶，再执行加减与规格化。

对阶时通常把小阶向大阶对齐，因为左移大阶的尾数会丢失高位。右移小阶尾数会丢失低位，但可以通过附加位与舍入减少误差。

浮点乘除法分别对尾数做乘除、对阶码做加减，然后规格化与舍入。乘除的阶码可能溢出，需要检查上下溢。

舍入方式包括：

- **就近舍入到偶数**：默认方式，减少统计偏差；
- **向零舍入**：截断，结果绝对值不大于精确值；
- **向正无穷舍入**：结果不小于精确值；
- **向负无穷舍入**：结果不大于精确值。

浮点运算不满足结合律。由于舍入误差，$(a+b)+c$ 与 $a+(b+c)$ 可能得到不同结果。数值计算中应避免相近数相减、避免大数吃小数，并在必要时使用更高精度或补偿求和。

### 浮点误差示例

十进制小数 0.1 与 0.2 无法用有限位二进制精确表示。单精度下：

```text
0.1 ≈ 0.100000001490116119384765625
0.2 ≈ 0.200000002980232238769531250
0.1 + 0.2 ≈ 0.300000011920928955078125
```

因此 `0.1 + 0.2 == 0.3` 在浮点运算中通常不成立。比较浮点数时应使用容差，例如判断绝对差是否小于 $10^{-6}$，而不是直接比较相等。

另一个典型问题是相近数相减。设单精度下 $a = 10^8$，$b = 1$，计算 $(a + b) - a$。由于单精度只有约 7 位有效数字，$a + b$ 中的 1 被舍入掉，结果为 0，而不是 1。这类误差称为大数吃小数。

浮点运算还应避免对大量数值直接累加。累加顺序会影响舍入误差，Kahan 求和等补偿算法可以提高精度。对精度要求高的计算，应使用双精度或更高精度，并对结果做误差分析。

## 结语

计算机组成原理围绕一条主线展开：指令如何在硬件上被执行。层次结构确定了软硬件的分工，冯·诺依曼结构规定了存储程序的工作方式，总线连接各部件，存储器提供指令与数据，I/O 完成与外部世界的交互，运算方法决定了数据如何被表示与计算。

理解这些部件时，应同时关注结构与性能。总线的宽度与频率决定带宽，Cache 的映射与替换决定命中率，存储层次决定平均访问时间，I/O 方式决定 CPU 的参与程度，浮点格式决定精度与范围。掌握这些关系，才能从整体上理解计算机的工作过程。
